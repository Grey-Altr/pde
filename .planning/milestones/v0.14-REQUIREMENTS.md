# Requirements: PDE v0.14 Visual AutoResearch

**Defined:** 2026-03-23
**Core Value:** Any user can go from idea to shipped product through a single platform that handles the full development lifecycle.

## v0.14 Requirements

Requirements for the Visual AutoResearch milestone. Playwright MCP browser automation enables a new class of AutoResearch experiments that optimize design skills against visual, accessibility, and structural metrics derived from actual browser rendering — not just text-based Nyquist assertions.

- [ ] **PLAY-01**: `@playwright/mcp` registered as 7th entry in mcp-bridge.cjs APPROVED_SERVERS with stdio transport, `npx @playwright/mcp@latest --headless` installCmd, and probe tool definition
- [ ] **PLAY-02**: TOOL_MAP entries for 10 Playwright tools: navigate, screenshot, snapshot, click, type, wait, evaluate, pdf, close, probe — all marked VERIFY_REQUIRED until live-verified
- [ ] **PLAY-03**: `--headless` hardcoded in APPROVED_SERVERS.installCmd — visible browser windows never spawn during autonomous execution (subagent worktrees, experiment loops)
- [ ] **PLAY-04**: Graceful degradation follows existing probe/degrade contract — all Playwright-dependent workflow steps have `--no-playwright` fallback paths
- [ ] **PLAY-05**: file:// URL navigation tested in Phase 1 — if restricted, fallback to `npx serve .planning/design/ux/wireframes/ -p 0` with random port
- [ ] **PLAY-06**: `references/mcp-integration.md` updated with Playwright server count, enhancement recipe, and tool name verification status
- [ ] **PLAY-07**: Tool name prefix (`mcp__playwright__*` format) live-verified before any workflow integration — same Phase 44 gate pattern used for Stitch
- [ ] **PLAY-08**: Playwright MCP process lifecycle managed by Claude Code session — no orphan Chrome processes after session end

### Visual Metric Scripts

- [ ] **VMET-01**: `bin/visual-metric.cjs` — renders wireframe/mockup HTML in Playwright, extracts DOM structure score via `browser_evaluate` (element count, heading hierarchy depth, landmark count, interactive element count, whitespace ratio) → returns single numeric score
- [ ] **VMET-02**: `bin/a11y-metric.cjs` — renders HTML in Playwright, extracts `browser_snapshot` AOM tree, counts violations (missing landmarks, missing ARIA labels, missing alt text, broken heading hierarchy) → returns violation count (lower is better)
- [ ] **VMET-03**: `bin/contrast-metric.cjs` — renders design token test page in Playwright, `browser_evaluate` measures WCAG AA contrast ratios for all text/background pairs → returns pass count
- [ ] **VMET-04**: `bin/responsive-metric.cjs` — renders HTML at 3 breakpoints (375px, 768px, 1280px) via `browser_resize`, checks for overflow, stacking violations, touch target sizes → returns compliance score
- [ ] **VMET-05**: `bin/mermaid-metric.cjs` — renders Mermaid flow diagram in browser via Mermaid JS, `browser_evaluate` counts nodes, edge crossings, label truncation → returns readability score
- [ ] **VMET-06**: All metric scripts exit 0 and print single numeric value to stdout — compatible with experiment runner `_evalMetric` contract (non-zero exit = CRASH)
- [ ] **VMET-07**: All metric scripts accept file path as first argument, handle missing Playwright gracefully (exit 0, print 0) for degradation
- [ ] **VMET-08**: `references/visual-metrics.md` documents all metric scripts, their scoring dimensions, and valid ranges

- [ ] **VBRK-03**: Baseline screenshot stored in `.planning/experiments/{slug}/baseline-screenshot.png` alongside EXPERIMENT-BEST.json
- [ ] **VBRK-04**: Visual regression breaker is opt-in per experiment via `visual_regression_guard: true` in experiment.md frontmatter — does not affect existing text-only experiments
