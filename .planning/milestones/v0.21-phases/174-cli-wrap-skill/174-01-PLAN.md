  <action>
    Create `bin/lib/app-cli-wrap.cjs` as a CJS module with these exported functions:

    1. **detectHarness(slug, pipxBinDir)** — Three-tier harness detection:
       - Tier 1: `spawnSync('which', ['cli-anything-' + slug], { encoding: 'utf8', timeout: 3000 })` — if status 0, return `{ found: true, binaryPath: stdout.trim() }`
       - Tier 2: If `pipxBinDir` is truthy, check `fs.existsSync(path.join(pipxBinDir, 'cli-anything-' + slug))` — if exists, return found with that path
       - Tier 3: Check well-known dirs `[path.join(os.homedir(), '.local', 'bin'), '/usr/local/bin']` — same existsSync check
       - All tiers fail: return `{ found: false, binaryPath: null }`

    2. **wrapViaHarness(cwd, slug, harnessBinaryPath, registryEntry)** — Fast path:
       - Log: `[cli-wrap] FAST PATH: using CLI-Anything harness at ${harnessBinaryPath}`
       - Call `discoverCapabilities(harnessBinaryPath)` from help-parser.cjs
       - Call `validateCapabilityModel({ meta: { source: harnessBinaryPath, type: 'cli', version: registryEntry.version || 'unknown', auth: {}, generatedAt: new Date().toISOString() }, capabilities })`
       - Output dir: `path.join(cwd, '.planning', 'app-wrappers', slug)` (NOT `.planning/cli-anything/`)
       - Write capability-model.json, call writeServer, call writeSkillMd
       - Return `{ strategy: 'harness', outDir, serverDir, capabilities: capabilities.length }`

    3. **wrapViaNativeHelp(cwd, slug, registryEntry)** — Fallback path:
       - Log: `[cli-wrap] FALLBACK PATH: no CLI-Anything harness found for '${slug}'`
       - Call `discoverCapabilities(registryEntry.binaryPath)`
       - Determine parseQuality: `capabilities.length < 3 ? 'degraded' : 'ok'`
       - Validate model with validateCapabilityModel (parseQuality NOT inside meta — Zod will reject unknown keys)
       - Write capability-model.json as `JSON.stringify({ ...model, parseQuality }, null, 2)` — parseQuality at top level OUTSIDE the validated model
       - Same writeServer + writeSkillMd calls
       - Return `{ strategy: 'fallback', outDir, serverDir, capabilities: capabilities.length, parseQuality }`

    4. **cmdCliWrap(cwd, args)** — Main orchestrator:
       - Extract slug from args[0]; if missing, print usage and process.exit(1)
       - Load config from `path.join(cwd, '.planning', 'config.json')` using `safeReadFile` from core.cjs; parse JSON; extract `config.clianything?.pipx_bin_dir || null`
       - If no pipx_bin_dir, console.warn about running pipx-setup
       - SECURITY: Call `checkApproved(registryPath, slug)` from app-registry.cjs BEFORE detectHarness — approval gate must happen before any binary probing
       - Call `detectHarness(slug, pipxBinDir)` — log the routing decision
       - If harness found: `await wrapViaHarness(cwd, slug, harness.binaryPath, registryEntry)`
       - If not: `await wrapViaNativeHelp(cwd, slug, registryEntry)`
       - Read capability-model.json from disk, call `registerDynamicServer(slug, serverPath, model.capabilities)`
       - Print summary: strategy, capabilities count, file paths, degraded quality warning if applicable

    5. **resolvePipxBinDir(_execFn)** — PIPX_BIN_DIR resolution with injectable exec for testing:
       - Strategy 1: `execFn('pipx', ['environment', '--value', 'PIPX_BIN_DIR'], { encoding: 'utf8', timeout: 5000 })` — return stdout.trim() if status 0
       - Strategy 2: `execFn('pipx', ['environment'], ...)` — regex match `PIPX_BIN_DIR\s*=\s*(.+)` on stdout
       - Strategy 3: `path.join(os.homedir(), '.local', 'bin')` if exists
       - Return null if all fail

    6. **storePipxBinDir(cwd, pipxBinDir)** — Direct JSON write to config.json (do NOT use config.cjs — VALID_CONFIG_KEYS blocks this key):
       - Read existing config.json or default to `{}`
       - Merge: `{ ...existing, clianything: { ...(existing.clianything || {}), pipx_bin_dir: pipxBinDir } }`
       - Write back with `JSON.stringify(updated, null, 2)`

    All dependency requires (`help-parser.cjs`, `server-gen.cjs`, `skill-gen.cjs`, `model.cjs`, `app-registry.cjs`, `mcp-bridge.cjs`, `core.cjs`) must use lazy `require()` inside functions, not at module top level. This matches the Phase 172 pattern and avoids load-order errors.
