<objective>
Implement orphan detection and nuclear reset for session worktrees, and wire orphan detection into PDE startup commands.

Purpose: Crashed or abandoned sessions leave worktrees behind. Without orphan detection, these accumulate silently and waste disk space. Without nuclear reset, there is no recovery path when things go wrong. Both are safety nets for the session isolation system. Per D-15, detection must trigger on startup commands — not just exist as a library function.

Output: packages/dispatcher/lib/orphan.cjs with detectOrphans and resetAllSessions, startup wiring in bin/lib/init.cjs, plus passing tests.
</objective>

  <action>
    **Step 1: Create packages/dispatcher/lib/orphan.cjs** (per D-15, D-16, D-17, D-20)
    Follow RESEARCH.md Pattern 3 reference implementation:

    `isProcessAlive(pid)`:
    - `try { process.kill(pid, 0); return true; } catch (e) { return e.code !== 'ESRCH'; }`
    - ESRCH = no such process (dead). EPERM = exists but no permission (alive).

    `detectOrphans(projectRoot, sessionRegistry)`:
    - `sessionRegistry` is a Map<sessionId, { pid, status, ... }> or null/undefined
    - Call `listSessionWorktrees(projectRoot)` from worktree.cjs
    - For each entry, extract sessionId from `entry.branch.replace('refs/heads/pde/session/', '')`
    - Look up sessionId in registry. If no entry or entry's PID is dead: push to orphans array
    - Orphan object shape: `{ sessionId, worktreePath: entry.worktree, branch: entry.branch.replace('refs/heads/', ''), status: 'dead_process' | 'unregistered' }`
    - Return orphans array (caller presents adopt/kill/ignore per D-16)

    `resetAllSessions(projectRoot)` (per D-17):
    - Call `listSessionWorktrees(projectRoot)`
    - For each session worktree:
      - Extract sessionId from branch
      - Call `removeWorktree(projectRoot, sessionId, { force: true })` — force remove even if dirty
      - Call `deleteBranch(projectRoot, entry.branch.replace('refs/heads/', ''), { force: true })` — `-D` to skip merge check
    - Catch errors per-session (one failure should not prevent cleaning others)
    - Call `execFileSync('git', ['worktree', 'prune'])` at end to clean up admin files
    - Return `{ removed: count }`

    Since Phase 143 has no parallel session registry yet, any `pde/session/*` worktree found at startup is by definition orphaned (RESEARCH.md Pitfall 7 confirms this is safe). Pass `null` as the sessionRegistry argument to `detectOrphans` — all found worktrees will be reported as "unregistered" orphans.

    **Step 1: Modify `cmdInitExecutePhase` in bin/lib/init.cjs**
    Add orphan detection before the final `output(result, raw)` call:
    ```javascript
    // ISO-04: Detect orphaned session worktrees at startup (per D-15)
    try {
      const { detectOrphans } = require('../../packages/dispatcher/lib/orphan.cjs');
      const orphans = detectOrphans(cwd, null);
      if (orphans.length > 0) {
        result.orphaned_sessions = orphans;
      }
    } catch (e) {
      // Dispatcher package not yet built (pre-phase-143) — silently skip
    }
    ```
    The try/catch ensures backward compatibility: if the dispatcher package does not exist yet (e.g., Plan 01 has not run), the init command still works normally. Once Plan 01 ships, the orphan detection activates automatically.

    **Step 2: Modify `cmdInitProgress` in bin/lib/init.cjs**

    **Important:** Do NOT add a `require` at the top of the file. Use lazy require inside the try/catch so the module only loads when needed and fails gracefully if not present.
