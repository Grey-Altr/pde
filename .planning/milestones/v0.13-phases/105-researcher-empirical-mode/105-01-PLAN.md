    **Part A: Create agents/pde-phase-researcher.md**

    Create a new agent definition file with YAML frontmatter and full empirical mode documentation.

    The agent file must:
    1. Have YAML frontmatter:
       - name: pde-phase-researcher
       - description: Research implementation approaches for PDE phases; gains --empirical flag for candidate generation mode
       - argument-hint: "[phase] [context-path] [--empirical]"
       - allowed-tools: Read, Glob, Grep, Write, Bash
       - model: sonnet

    2. Standard mode description (existing behavior):
       - Researcher reads CONTEXT.md (decisions from /pde:discuss-phase), REQUIREMENTS.md, STATE.md
       - Produces RESEARCH.md with implementation approach, stack analysis, integration points
       - Returns `## RESEARCH COMPLETE` with summary

    3. Empirical mode (NEW — activated by --empirical flag):
       - When --empirical is passed, the researcher ALSO produces a try_candidates list
       - Each candidate is a bounded, testable mutation — not a general recommendation
       - Candidates should be specific: which files, what to change, expected measurable effect
       - Confidence levels: HIGH (well-understood pattern), MEDIUM (reasonable hypothesis), LOW (speculative)
       - Researcher still produces the full RESEARCH.md — empirical mode is ADDITIVE, not replacing

    4. Return format for empirical mode:
       ```json
       {
         "status": "RESEARCH_COMPLETE",
         "research_file": ".planning/phases/{N}-{slug}/RESEARCH.md",
         "mode": "empirical",
         "try_candidates": [
           {
             "id": "C1",
             "description": "One-sentence description of the proposed change",
             "mutable_files": ["workflows/example.md"],
             "change_summary": "Specific description of what to add/modify/remove",
             "expected_delta": "+3 to +8 metric points",
             "confidence": "MEDIUM"
           }
         ]
       }
       ```

    5. RESEARCH.md template for empirical mode must include:
       ```
       ## Experiments Attempted

       | ID | Description | Files | Outcome |
       |----|-------------|-------|---------|
       | C1 | ... | ... | KEEP/DISCARD/CRASH |
       ```
       This section is populated by the optimize workflow after running candidates through the experiment loop.
       When the researcher is running (before experiments execute), this section is left as a placeholder with headers only.

    6. Standard return for desk research mode (no --empirical):
       ```
       ## RESEARCH COMPLETE
       ```
       Followed by summary prose. No try_candidates field.
