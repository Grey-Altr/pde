## Summary

Phase 134.1 is a targeted bug-fix and documentation-hygiene phase. There is a single critical production bug: the relay daemon tails the wrong NDJSON file because `start-relay.cjs` reads `hookData.session_id` (Claude's own conversation ID) while `event-bus.cjs`/`pde-tools.cjs` writes NDJSON using a PDE-generated UUID stored in `.planning/config.json`. This namespace mismatch means the relay polls a file that is never written to in production.

The fix is minimal and well-scoped. `start-relay.cjs` must read the PDE session UUID from `.planning/config.json` (`monitoring.session_id`) rather than from the hook payload. This is safe because `emit-event.cjs` runs with `async: false` in SessionStart before `start-relay.cjs` (which runs `async: true`), meaning the PDE UUID is guaranteed to be persisted before the relay hook reads it. A new integration test must exercise the hook spawn path — the existing e2e tests call `startRelay()` directly and therefore never caught this mismatch.

The tech debt items are documentation fixes: two SUMMARY frontmatter fields missing `requirements-completed`, one ROADMAP.md checkbox, and one REQUIREMENTS.md traceability table.

**Primary recommendation:** Fix `start-relay.cjs` to read `config.monitoring.session_id`, add a single integration test that exercises the full hook → spawn → tail path with a PDE UUID, then update the four documentation artifacts. No new libraries. No architectural changes.

## Root Cause Analysis (HIGH confidence)

### The Bug: Session ID Namespace Mismatch

**Where PDE writes events:**
- `bin/pde-tools.cjs` case `session-start` (line 761): generates `randomUUID()`, writes to `.planning/config.json` as `monitoring.session_id`
- `bin/pde-tools.cjs` case `event-emit` (line 797-800): reads session_id from `config.json` → `monitoring.session_id`
- `bin/lib/event-bus.cjs` line 50: `safeAppendEvent(sessionId, envelope)` writes to `/tmp/pde-session-{pde-uuid}.ndjson`

**Where the relay looks for events:**
- `hooks/start-relay.cjs` line 42: `const sessionId = hookData.session_id || ''`
- `hookData.session_id` is the Claude Code conversation ID from the hook JSON payload — NOT the PDE UUID
- `bin/lib/relay.cjs` line 352: `path.join(os.tmpdir(), 'pde-session-${sessionId}.ndjson')` — tails `/tmp/pde-session-{claude-conv-id}.ndjson`

**Result:** Relay tails a file that does not exist. Events are written to `/tmp/pde-session-{pde-uuid}.ndjson`. Relay watches `/tmp/pde-session-{claude-conv-id}.ndjson`. No events are ever relayed in production.

**Why all 33 tests pass:** The test for `test-relay-hooks.cjs` (Test 2) spawns `start-relay.cjs` with a randomly-generated UUID as `session_id` in the hook payload — this happens to be the same UUID the relay watches. The e2e tests (`test-relay-e2e.cjs`) call `startRelay(sessionId, ...)` directly, completely bypassing the hook spawn path. Neither test exercises the production path where the hook payload session_id differs from the config.json session_id.

### The Fix

`start-relay.cjs` must read the PDE session UUID from `.planning/config.json` instead of from the hook payload:

```javascript
// CURRENT (broken):
const sessionId = hookData.session_id || '';

// FIXED:
const pluginRoot = process.env.CLAUDE_PLUGIN_ROOT || path.resolve(__dirname, '..');
const configPath = path.join(pluginRoot, '.planning', 'config.json');
let sessionId = '';
try {
  const cfg = JSON.parse(fs.readFileSync(configPath, 'utf-8'));
  sessionId = (cfg.monitoring && cfg.monitoring.session_id) || '';
} catch { /* swallow — exit 0 below if empty */ }
```

**Why this is safe:** The SessionStart hook execution order in `hooks.json` is:
1. `emit-event.cjs` (async: false) — calls `pde-tools.cjs session-start`, which writes `monitoring.session_id` to config.json
2. `cleanup-old-sessions.cjs` (async: false)
3. `context-sync-session-start.cjs` (async: true)
4. `start-relay.cjs` (async: true)

`emit-event.cjs` runs synchronously before `start-relay.cjs` begins, so config.json is guaranteed to contain the PDE UUID when the relay reads it.

**What to do with `hookData.session_id`:** It can be retained as a fallback comment or logged for debugging, but should not be used as the NDJSON file path suffix.

## Architecture Patterns

### Pattern 1: Config.json as Session ID Authority
**What:** `pde-tools.cjs session-start` is the single source of truth for the PDE session UUID. It writes to `.planning/config.json` → `monitoring.session_id`. All consumers (event-emit, suggestions, start-relay) must read from this location.
**Example (from pde-tools.cjs lines 796-800):**
```javascript
const cfg = JSON.parse(fs.readFileSync(configPath, 'utf-8'));
if (cfg.monitoring && cfg.monitoring.session_id) {
  sessionId = cfg.monitoring.session_id;
}
```
**Note:** `stop-relay.cjs` also uses `hookData.session_id` to look up the PID file. After the fix, start-relay writes the PID file using the config.json UUID, so stop-relay must read from the same source. Both must be consistent.

### Pattern 2: Hook Ordering Guarantee
**What:** `async: false` hooks in hooks.json run and complete before `async: true` hooks start for the same event.
**Implication:** The `emit-event.cjs` (async:false) → `pde-tools.cjs session-start` call chain writes `config.json` before `start-relay.cjs` (async:true) reads it. No race condition.

### Pattern 3: CJS Test Files with vitest globals:true
**What:** All test files in `tests/phase-134/` use vitest 4.1.1 with `globals: true` in `vitest.config.ts`. Test APIs (`describe`, `it`, `expect`, `vi`, `beforeEach`) are injected globally — do NOT use `require('vitest')`.
**Command:** `npx vitest run tests/phase-134.1/ --reporter=verbose`

## Common Pitfalls

### Pitfall 1: Forgetting to Fix stop-relay.cjs to Match
**What goes wrong:** After fixing `start-relay.cjs` to write the PID file using the config.json UUID, `stop-relay.cjs` still reads `hookData.session_id` to find the PID file. The PID file path won't match and the relay daemon leaks after session end.
**How to avoid:** Fix both start-relay.cjs and stop-relay.cjs to use `config.monitoring.session_id` as the session ID key for PID file naming. Read stop-relay.cjs carefully before writing the fix.
**Current stop-relay.cjs pattern:**
```javascript
let hookData;
try { hookData = JSON.parse(raw); } catch { hookData = {}; }
const sessionId = hookData.session_id || '';
const pidFile = path.join(os.tmpdir(), `pde-relay-${sessionId}.pid`);
```
This must also be updated to read from config.json.

### Pitfall 2: Integration Test Still Calling startRelay() Directly
**What goes wrong:** A new test file is added but still calls `startRelay(uuid, ...)` directly, not through the hook spawn path. The namespace mismatch regression would not be caught.
**How to avoid:** The integration test for the hook spawn path must:
1. Write a PDE UUID to a temp config.json (`monitoring.session_id`)
2. Spawn `start-relay.cjs` via `spawnSync` with a DIFFERENT value as `hookData.session_id`
3. Verify the relay daemon tails the config.json UUID's NDJSON file, not the hook payload's session_id file
4. Write events to `/tmp/pde-session-{config-uuid}.ndjson` and confirm they arrive at the mock server

### Pitfall 3: config.json Path Resolution in Hook Scripts
**What goes wrong:** The `pluginRoot` in hook scripts uses `CLAUDE_PLUGIN_ROOT || path.resolve(__dirname, '..')`. The config.json is at `{pluginRoot}/.planning/config.json`. In tests, CWD may differ from where config.json was written.
**How to avoid:** Use `pluginRoot` (already defined in start-relay.cjs line 21) for the config path, same as pde-tools.cjs uses CWD. In tests, set `CLAUDE_PLUGIN_ROOT` env var to a temp directory and write config.json there.

### Pitfall 4: Test 2 in test-relay-hooks.cjs Masks the Bug After the Fix
**What goes wrong:** After the fix, Test 2 currently passes `session_id` in the hook payload AND has no config.json, so `sessionId` from config would be empty and the hook would exit 0 without spawning. Test 2 would start failing for the wrong reason.
**How to avoid:** Update Test 2 to also write a temp config.json with `monitoring.session_id` set, so the fixed hook can find the PDE UUID. The test then verifies the PID file is named with the config UUID, not the hook payload session_id.

### Pitfall 5: SUMMARY frontmatter field name
**What goes wrong:** The field is `requirements-completed` (with hyphen). Plans 02 and 03 SUMMARY.md files have `dependency_graph.provides` and `tech_stack.patterns` but lack the top-level `requirements-completed: [RLY-XX]` field.
**Evidence from Plan 01 SUMMARY.md (line 50):** `requirements-completed: [RLY-02]`
**Plans 02 and 03 are missing this.** Plan 02 should have `[RLY-01, RLY-03]`. Plan 03 should have `[RLY-04, RLY-05]`.

## New Integration Test: Hook Spawn Path

**Purpose:** Catch the session ID namespace mismatch class of bug — where hook reads different session_id than event-bus writes.

**Test location:** `tests/phase-134.1/test-relay-hook-session-id.cjs`

**What the test must exercise:**
1. Create a temp directory as pluginRoot
2. Write `config.json` with `monitoring.session_id = 'pde-uuid-abc123'` (the PDE UUID)
3. Set up a mock HTTP server on port 0
4. Spawn `start-relay.cjs` via `spawnSync` with:
   - `CLAUDE_PLUGIN_ROOT` = temp dir
   - `PDE_REMOTE` = mock server URL
   - hook payload `session_id = 'claude-conv-id-xyz'` (a DIFFERENT value)
5. Write events to `/tmp/pde-session-pde-uuid-abc123.ndjson`
6. Wait for events to arrive at mock server
7. Assert: events arrived (relay tailed the config UUID file)
8. Assert: NO events would have arrived if relay had tailed the hook payload session_id file

**Key assertion:** The relay daemon tails the config.json PDE UUID file, not the hook payload session_id file.
