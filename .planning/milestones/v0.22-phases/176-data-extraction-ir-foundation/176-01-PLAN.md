    ```javascript
    'use strict';
    ```

    **Function 1: extractProjectIdentity(cwd)**
    - Read `.planning/PROJECT.md` via safeReadFile
    - If null, return `{ unavailable: true, reason: 'PROJECT.md not found' }`
    - Extract `name` from first `# ` heading line
    - Extract `goal` from first paragraph after heading (or from a `## Goal` section if present)
    - Extract `core_value` from `## Core Value` or `**Core value:**` pattern (check STATE.md pattern: `**Core value:** Any user can go from idea to shipped product...`)
    - Extract `product_type` from design-manifest.json `productType` field (safeReadFile + JSON.parse), fallback to 'unknown'
    - Extract `summary` from first 2 paragraphs of PROJECT.md body
    - Return `{ name, goal, core_value, product_type, summary }`

    **Function 2: extractPhaseCompletion(cwd)**
    - Read `.planning/STATE.md` via safeReadFile. If null, return unavailable sentinel.
    - Parse frontmatter with extractFrontmatter to get `progress.total_phases`, `progress.completed_phases`, `progress.total_plans`, `progress.completed_plans`, `milestone`, `milestone_name`, `status`
    - Use stateExtractField pattern (inline, not imported) to extract `Phase:` line for current_phase number and name
    - Read `.planning/ROADMAP.md` to count current milestone phases: match `- [ ]` and `- [x]` lines under the current milestone heading
    - Compute `progress_percent` from frontmatter or calculate as `(completed / total * 100)`
    - Return the full phases object per IR schema

    **Function 3: extractRequirements(cwd)**
    - Read `.planning/REQUIREMENTS.md` via safeReadFile. If null, return unavailable sentinel.
    - Split content by `### ` headers to get category sections (skip content before first ###)
    - For each section: extract category name from header, match `- [([ x])]\s+\*\*([A-Z]+-\d+)\*\*` for checkboxes
    - Count total, completed (x), blocked (look for "blocked" in description text after ID)
    - Pending = total - completed - blocked
    - Return `{ total, completed, blocked, pending, categories: { [name]: { total, completed, blocked } } }`
    - Filter out `## Future Requirements` and `## Out of Scope` sections — only parse `## v1 Requirements` content

    **Function 4: extractDesignArtifacts(cwd)**
    - Read `.planning/design/design-manifest.json` via safeReadFile + JSON.parse. If null or parse fails, return unavailable sentinel.
    - Extract artifact_count from manifest.artifacts array length (or 0)
    - Extract types_covered from unique artifact type values
    - Check has_tokens (manifest.tokens exists and is non-empty), has_wireframes (any artifact with type 'wireframe'), has_mockups (any artifact with type 'mockup')
    - Return the design_artifacts object

    **Export all four functions:**
    ```javascript
    module.exports = { extractProjectIdentity, extractPhaseCompletion, extractRequirements, extractDesignArtifacts };
    ```
