## Layout Contract

`TokenPlayground` replaces `CostMeter` in `session-detail.tsx`. It renders as a single React component outputting three stacked Card sections inside a `div` with `space-y-4` (16px gap), matching the existing session-detail layout rhythm.

```
session-detail.tsx
  <div className="space-y-4">
    StatusCard
    [ApprovalCard — conditional]
    PhaseProgress
    TokenPlayground          <-- replaces CostMeter here
      Card "Context Window"
        Progress bar h-2
        Label line below bar
      Card "Session Cost"
        3-column grid (Input | Output | Est. Cost)
      Card "Per-Agent Breakdown"
        Table: Agent | Tool Calls | Input | Output | Cost
    EventLog
  </div>
```

### Card: Context Window

- Card heading: "Context Window" — `text-sm font-semibold`
- `<Separator className="my-2" />` below heading
- `<Progress value={percentUsed} className="h-2" />` — value 0 to 100
- Below Progress: single `<p className="text-xs text-muted-foreground">` showing:
  `"{formattedInputTokens} input tokens • {percentUsed.toFixed(1)}% context est."`
- Context window denominator: 1,000,000 tokens (Sonnet 4.6 / Opus 4.6 default per RESEARCH.md)
- When `connectionStatus === 'reconnecting'`: apply `opacity-60` to the entire card content (matches CostMeter precedent)

### Card: Session Cost

- Card heading: "Session Cost" — `text-sm font-semibold`
- `<Separator className="my-2" />`
- 3-column grid `grid grid-cols-3 gap-2 text-center`:
  - Column 1: `{formatTokens(totalInputTokens)}` — label "Input"
  - Column 2: `{formatTokens(totalOutputTokens)}` — label "Output"
  - Column 3: `{formatCost(totalCostUsd)}` — label "Est. Cost"
- Values: live from `deriveCost(events)` + `initialPersistedCostUsd` prop seed for first render
- When `connectionStatus === 'reconnecting'`: apply `opacity-60`

### Card: Per-Agent Breakdown

- Card heading: "Per-Agent Breakdown" — `text-sm font-semibold`
- `<Separator className="my-2" />`
- Table with columns: Agent | Tool Calls | Input | Output | Cost
- Column widths: Agent col flex-1, remaining cols fixed text-right
- Row data: one row per `ToolCostRow` from `deriveToolBreakdown(events)`
- Agent ID display: `<Badge variant="secondary">` wrapping the agent ID string (truncated to 12 chars + "…" if longer)
- Numeric cells: `font-mono text-sm`
- Cost cell: `formatCost(row.estimatedCostUsd)` — `font-mono text-sm`
- When empty (no rows): render the empty state (see Copywriting Contract below)
- When `connectionStatus === 'reconnecting'`: apply `opacity-60` to table content

## Interaction States

| State | Visual Treatment |
|-------|-----------------|
| Loading (initial SSR hydration) | `Skeleton` component, full card width, h-4 height, for all three cards |
| Live (events flowing) | Cards display computed values, no shimmer |
| Reconnecting | `opacity-60` on all three card bodies — matches CostMeter precedent |
| Empty breakdown (no token_usage events yet) | Per-Agent Breakdown card shows empty state copy in `text-sm text-muted-foreground` centered |
| Error (Redis write failure) | Inline `text-xs text-destructive` below Session Cost card: error copy |
| Overflow (context > 100%) | Progress value clamped to 100 via `Math.min(percentUsed, 100)` — no visual overflow indicator needed |

No hover animations, no focus rings (non-interactive display elements). The Progress bar uses shadcn's built-in CSS transition for value changes — do not add a custom animation.

## Data Contract (Component Props)

```typescript
interface TokenPlaygroundProps {
  events: WireEnvelope[];
  connectionStatus: ConnectionStatus;
  sessionId: string;
  initialPersistedCostUsd: number;   // from Redis SSR hydration; 0 for new sessions
}
```

These props are supplied by `session-detail.tsx` (or its parent Server Component for the `initialPersistedCostUsd` value). The executor must thread `initialPersistedCostUsd` from the page's SSR data-fetch into `SessionDetail` and down into `TokenPlayground`.

## Persist Behavior (UX Contract)

- On mount with `totalInputTokens > 0`: debounced Server Action call after 5 seconds of quiet
- Debounce reset: each new `token_usage` event resets the 5-second timer
- On unmount with pending debounce: cancel the timer (no flush-on-unmount)
- Rationale: avoids Upstash command exhaustion on the free tier; documented in RESEARCH.md Pitfall 2
