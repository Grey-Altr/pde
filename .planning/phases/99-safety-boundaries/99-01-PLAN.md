## Experiment Boundary Reference
Brief intro: This document defines what is permanently immutable vs. what can be modified during autonomous experiments. Read by `experiment.cjs` at startup for SAFE-04 validation.

## Default Policy
Unannotated files are treated as LOCKED by default, not OPTIMIZABLE. An experiment-eligible file missing both markers produces a validation warning.

## Locked Zones
### Eval Harness
- All files in `tests/` directory (Nyquist suite — 78 test files, 952+ assertions)
- `references/quality-standards.md` (Awwwards rubric)
- This file (`references/experiment-boundaries.md`)

### Core Infrastructure
- All files in `bin/` (pde-tools.cjs and library modules)
- All files in `agents/` (agent definitions — circular risk if experiment modifies its own agent)
- All files in `.claude/` (Claude Code settings)
- All files in `.planning/` except `.planning/experiments/`
- `protected-files.json`, `CLAUDE.md`, `skill-registry.md`

### Infrastructure Workflows
Explain that workflows in the `infrastructure_workflows` YAML list are locked even though they live in `workflows/`. These orchestrate PDE itself — mutation risks breaking the planning pipeline.

### Protected Files List
Reference to `protected-files.json` as the prompt-enforcement layer. `experiment-boundaries.md` is the experiment-enforcement layer. Both apply independently.

## Optimizable Zones
### Workflow Prose
The 14 design skill workflows (brief, system, flows, ideate, wireframe, critique, hig, iterate, recommend, mockup, competitive, opportunity, handoff, deploy) contain sections with `<!-- OPTIMIZABLE -->` markers. Only content within these markers is eligible for mutation.

### What Is Optimizable Within a Workflow
- Prose action descriptions within a step
- Example output sections
- Heuristic ordering within a step
- Prompt phrasing for agent instructions
- Scoring rubric description text (not field names)

### What Is LOCKED Within a Workflow (Even in Experiment-Eligible Files)
- Step 1 (init) — pde-tools.cjs calls, JSON parsing, prerequisite validation
- Artifact schema writes — designCoverage field names, artifact code values, file path patterns
- Error message formats asserted by Nyquist tests
- MCP probe patterns (bridge.call blocks)
- Required reading blocks (@references/ includes)
- Frontmatter, purpose, and flags sections

## Marker Syntax
Document the `<!-- LOCKED -->` / `<!-- /LOCKED -->` and `<!-- OPTIMIZABLE -->` / `<!-- /OPTIMIZABLE -->` paired open/close comment syntax. Interleaved markers are valid. Each marker can optionally include a description: `<!-- LOCKED: init step -- infrastructure -->`.
