    **1. SSE endpoint: `dashboard/app/api/events/route.ts`** (per Pattern 1 and Pattern 2 from RESEARCH.md, D-04):

    ```typescript
    export const dynamic = 'force-dynamic';
    export const maxDuration = 300; // Fluid Compute Hobby max
    ```

    GET handler:
    - Authenticate via `auth()` from `@clerk/nextjs/server` — return 401 if not authenticated
    - Read `session` query param from URL searchParams — return 400 if missing
    - Read `Last-Event-ID` header (sent automatically by EventSource on reconnect) — default to '0'
    - Create a `ReadableStream` with:
      a. `start(controller)`: Send initial `data: {"type":"connected"}\n\n` event
      b. Start a 15-second heartbeat interval sending `: heartbeat\n\n` (SSE comment, not dispatched to message handlers)
      c. Start a 2-second polling loop inside the stream that:
         - Calls `redis.zrangebyscore(`pde:default:events:${sessionId}`, lastScore + 1, '+inf', { count: 50 })` (or equivalent Upstash method — read Upstash SDK docs for exact method signature)
         - For each event returned, encode as SSE: `id: ${score}\nevent: pde-event\ndata: ${JSON.stringify(event)}\n\n`
         - Update lastScore cursor
      d. On `req.signal.addEventListener('abort', ...)`: clear heartbeat interval, clear polling interval, close controller
    - Return `new Response(stream, { headers: { 'Content-Type': 'text/event-stream; charset=utf-8', 'Cache-Control': 'no-cache, no-transform', 'Connection': 'keep-alive', 'X-Accel-Buffering': 'no' } })`

    **2. Polling fallback: `dashboard/app/api/poll/route.ts`** (per D-05, D-06):

    ```typescript
    export const dynamic = 'force-dynamic';
    ```

    GET handler:
    - Authenticate via `auth()` from `@clerk/nextjs/server` — return 401 if not authenticated
    - Read query params: `session` (required), `last_ts` (default '0')
    - Query Redis: `redis.zrangebyscore(`pde:default:events:${session}`, Number(last_ts) + 1, '+inf')` — fetch events newer than cursor
    - Parse each member (stored as JSON string) back to object
    - Return JSON: `{ events: [...], cursor: lastScore }` where cursor is the score of the last event returned (or last_ts if no new events)

    - Test: request with last_ts returns only newer events

  <action>
    Create `dashboard/hooks/use-event-stream.ts` implementing the client-side SSE + polling fallback hook (per Pattern 8 from RESEARCH.md, D-04, D-05, D-06).

    The hook signature:
    ```typescript
    "use client";

    export type ConnectionStatus = 'connecting' | 'connected' | 'reconnecting' | 'polling';

    export interface UseEventStreamReturn {
      events: WireEnvelope[];
      connectionStatus: ConnectionStatus;
    }

    export function useEventStream(sessionId: string): UseEventStreamReturn
    ```

    Implementation:
    1. State: `events` array (WireEnvelope[]), `connectionStatus` (ConnectionStatus), `lastTs` ref (number, cursor), `usingPolling` state (boolean)
    2. SSE mode (when `usingPolling === false`):
       - Create `new EventSource(`/api/events?session=${sessionId}`)`
       - On open: set connectionStatus to 'connected'
       - On message event `pde-event`: parse data, append to events, update lastTs cursor, reset heartbeat timer
       - Heartbeat timer: `setTimeout(() => setUsingPolling(true), 30_000)` — reset on every message or comment received
       - Note: EventSource does NOT fire onmessage for SSE comments (`: heartbeat`). To detect heartbeats, we rely on the fact that any real data event resets the timer. If no data events AND no heartbeat for 30s, fall back. The EventSource onerror also triggers fallback.
       - On error: set connectionStatus to 'reconnecting'. After 2 consecutive errors, switch to polling.
       - Cleanup: close EventSource, clear heartbeat timer
    3. Polling mode (when `usingPolling === true`):
       - Set connectionStatus to 'polling'
       - Start 3-second interval (per D-05): `fetch(`/api/poll?session=${sessionId}&last_ts=${lastTs.current}`)`
       - Parse response, append new events, update lastTs cursor
       - Every 10th poll cycle, attempt SSE reconnect by setting `usingPolling(false)`
       - Cleanup: clear interval
    4. Events array: Maintain a rolling buffer of last 200 events (prevent unbounded memory in long sessions). New events prepended (newest first for display).
    5. Export `connectionStatus` so UI can show "Reconnecting..." or "Live (polling)" badges per UI-SPEC interaction contract.
  </action>
