  <action>
    **1. Create `commands/optimize.md`** following the execute-phase.md pattern exactly:

    Use the same YAML frontmatter structure as commands/execute-phase.md. Set:
    - name: pde:optimize
    - description: Run an autonomous optimization experiment loop against an experiment.md file
    - argument-hint: (experiment.md path) (--self) (--skill name) (--dry-run)
    - allowed-tools: Read, Write, Bash, Task, AskUserQuestion

    The objective section says: Execute the /pde:optimize workflow.
    The execution_context references: @${CLAUDE_PLUGIN_ROOT}/workflows/optimize.md
    The process section delegates to workflows/optimize.md with $ARGUMENTS passthrough.

    **2. Create `workflows/optimize.md`** (~200 lines) with these numbered steps:

    **Step 1: Parse Arguments and Validate**
    - Parse $ARGUMENTS to extract experiment.md path (or --self/--skill flags -- these are Phase 104 concerns, so for now log "preset mode not yet implemented" and abort if --self or --skill passed without an experiment.md path)
    - Read the experiment.md file directly with the Read tool, extract the slug from frontmatter. Validate required fields (metric, direction, verify, mutable_files). If any field missing, abort with clear error.
    - Load experiment_defaults from `.planning/config.json` via the Read tool. Merge: experiment.md frontmatter overrides (iteration_budget, time_budget_minutes) take precedence over config.json defaults. For consecutive_failure_limit and no_progress_limit, use config.json values (not in experiment.md frontmatter).

    **Step 2: Clean Working Tree Check**
    - Run: `git status --porcelain`
    - If any output (excluding lines starting with `?? .planning/experiments/`), abort: "Cannot start experiment: uncommitted changes detected. Commit or stash before running /pde:optimize."

    **Step 3: Concurrency Check**
    - Run: `git branch --list 'experiment/*'`
    - If any branches exist, warn user via AskUserQuestion: "Active experiment branch found: {branch}. Running a new experiment while another is active risks git conflicts. Continue? [yes/no]"
    - If user says no, abort.

    **Step 4: Cost Estimate Gate (BREAK-05)**
    - Calculate estimated tokens: `iterationBudget * 2000` (the _estimateCost formula from experiment-report.cjs)
    - Display to user: "Estimated token cost: ~{tokens} tokens ({iterations} iterations x ~2000 tokens/iteration)"
    - If `cost_estimate_enabled` is true in config.json experiment_defaults:
      - Ask user via AskUserQuestion: "Proceed with experiment? [yes/no]"
      - If no, abort: "Experiment cancelled by user at cost estimate gate."
    - If --dry-run flag was passed, display the estimate and abort without starting the loop: "Dry run complete. No iterations executed."

    **Step 5: Initialize Experiment Branch**
    - Run: `node bin/pde-tools.cjs experiment init --slug {slug}`
    - This creates the experiment/{slug} branch and initial EXPERIMENT-BEST.json

    **Step 6: Capture Baseline Metric**
    - Copy experiment.md to `.planning/experiments/{slug}/experiment.md` (the runner needs it there)
    - Run: `node bin/pde-tools.cjs experiment eval-metric --slug {slug}`
    - Parse the JSON output to get `metric_value` -- this is the baseline
    - Store `baselineMetric` for REPORT.md generation later
    - Display: "Baseline metric: {value}"

    **Step 7: Iteration Loop**
    - Initialize loop state variables:
      - `currentIteration = 0`
      - `consecutiveFailures = 0`
      - `iterationsSinceImprovement = 0`
      - `consecutiveViolations = 0`
      - `currentModel = "pde-experiment-runner"` (haiku by default)
      - `startTimeSeconds` (capture via Bash: `date +%s` at loop start)
      - `haltReason = null`

    - LOOP (while haltReason is null):
      a. Increment `currentIteration`
      b. Determine context_mode: "full" if iteration 1, "diff" otherwise
      c. Read last 3 rows from `.planning/experiments/{slug}/results.jsonl` (if exists) via Read tool or `tail -3`
      d. Dispatch runner agent via Task() with subagent_type set to currentModel. The prompt includes:
         - objective: Run experiment iteration N for slug
         - files_to_read: .planning/experiments/{slug}/experiment.md
         - additional_context: Iteration number, Baseline SHA, Context mode (full or diff), Last 3 results rows
      e. Parse the JSON response from Task(). Extract: status, metric_value, metric_delta, description, tokens_used
      f. Display iteration result: "Iteration {N}: {status} | metric={metric_value} | delta={metric_delta}"

      g. Update loop state based on status:
         - If status === "KEEP":
           - consecutiveFailures = 0, iterationsSinceImprovement = 0, consecutiveViolations = 0
         - If status === "DISCARD":
           - consecutiveFailures++, iterationsSinceImprovement++, consecutiveViolations = 0
         - If status === "CRASH" or "BOUNDARY_VIOLATION":
           - consecutiveFailures++, iterationsSinceImprovement++, consecutiveViolations++

      h. Model escalation check (SELF-07):
         - If consecutiveViolations >= 3 AND currentModel === "pde-experiment-runner":
           - Switch to "pde-experiment-runner-sonnet"
           - Display: "Escalating to Sonnet model after N consecutive violations"

      i. Calculate elapsedMinutes: `(currentTimeSeconds - startTimeSeconds) / 60`

      j. Check circuit breakers in order (first to fire halts the loop):
         1. BREAK-01: if currentIteration >= iterationBudget -> haltReason = "iteration_budget"
         2. BREAK-02: if elapsedMinutes >= timeBudget -> haltReason = "time_budget"
         3. BREAK-03: if consecutiveFailures >= consecutiveFailureLimit -> haltReason = "consecutive_failures"
         4. BREAK-04: if iterationsSinceImprovement >= noProgressLimit -> haltReason = "no_progress"
         - If any fires, display: "Circuit breaker fired: {haltReason} at iteration {currentIteration}"

    **Step 8: Generate REPORT.md (SELF-05)**
    - Run: `node bin/pde-tools.cjs experiment generate-report --slug {slug}`
    - Read the generated `.planning/experiments/{slug}/REPORT.md`
    - Display the Summary table to the user

    **Step 9: Promotion Approval (SELF-04)**
    - Run: `node bin/pde-tools.cjs experiment diff-summary --slug {slug}`
    - Display the diff to the user (truncate to 50 lines if longer, with "... N more lines" footer)
    - Ask via AskUserQuestion: "Merge these improvements to main? Review the diff above. [yes/no]"
    - If yes:
      - Run: `node bin/pde-tools.cjs experiment promote --slug {slug}`
      - Display: "Experiment {slug} promoted to main successfully."
    - If no:
      - Run: `node bin/pde-tools.cjs experiment cleanup --slug {slug}`
      - Display: "Experiment branch cleaned up. Changes discarded."

    **Important anti-patterns to avoid (from RESEARCH.md):**
    - Do NOT put circuit breaker logic in Node.js -- check as workflow IF conditionals
    - Do NOT update EXPERIMENT-BEST.json from the orchestrator -- the runner updates it via experiment commit
    - Do NOT hardcode circuit breaker defaults -- always read from config.json merged with experiment.md
    - Do NOT write REPORT.md inside the runner -- it is a post-loop artifact
    - Do NOT skip cost estimate display for --dry-run (it is still useful)
