## Phase Details

### Phase 99: Safety Boundaries
**Goal**: All experiment-eligible workflow files have machine-enforceable locked and optimizable zone markers, and a canonical reference defines what is permanently immutable vs what can be modified
**Depends on**: Phase 98 (v0.12 complete baseline)
**Requirements**: SAFE-01, SAFE-02, SAFE-03, SAFE-04
**Success Criteria** (what must be TRUE):
  1. `references/experiment-boundaries.md` exists and enumerates locked zones (eval harness, core infrastructure, protected-files) and optimizable zones (workflow prose, agent prompts, skill instructions)
  2. Every experiment-eligible workflow file contains at least one `<!-- LOCKED -->` section and at least one `<!-- OPTIMIZABLE -->` section
  3. The Nyquist test files and Awwwards rubric references are listed in the protected-files list and will be rejected if a mutable file list targets them
  4. A mutable file list referencing a locked file (e.g. a Nyquist test file) produces an explicit rejection message rather than silently proceeding
**Plans**: 2 plans

Plans:
- [x] 99-01-PLAN.md — Create experiment-boundaries reference and update protected-files.json
- [x] 99-02-PLAN.md — Add LOCKED/OPTIMIZABLE markers to 14 experiment-eligible workflow files

### Phase 100: Git State Machine
**Goal**: A reliable git state machine exists as a standalone CJS module that can commit experiment candidates, tag best results, and reset to baseline without touching regular planning commits
**Depends on**: Phase 99
**Requirements**: GIT-01, GIT-02, GIT-03, GIT-04, GIT-05
**Success Criteria** (what must be TRUE):
  1. `bin/lib/experiment.cjs` implements `commitCandidate`, `resetToBaseline`, `promoteBest`, and boundary check functions, all under 300 lines total
  2. Running `pde-tools experiment reset` on a commit with `experiment({slug}):` prefix reverts it; running it on a `planning:` commit is rejected without any change
  3. Experiment commits never appear in the main branch git log — they exist only on the experiment branch until explicitly promoted
  4. `EXPERIMENT-BEST.json` is written after each kept iteration and can be used to resume an interrupted experiment session
  5. All 6 pde-tools experiment subcommands (`init`, `commit`, `reset`, `promote`, `status`, `cleanup`) are dispatched correctly and produce structured output
**Plans**: 2 plans

Plans:
- [x] 100-01-PLAN.md — Implement experiment.cjs git state machine module
- [x] 100-02-PLAN.md — Wire 6 experiment subcommands into pde-tools.cjs dispatch

**Depends on**: Phase 100

  3. `config.json` contains an `experiment_defaults` block with default iteration budget, time budget, consecutive-failure limit, no-progress limit, and cost-estimate toggle
  4. ROADMAP.md experiment phase type entries are recognized by downstream plan-phase tooling (target metric, search space, and budget fields are present)

### Phase 102: Mutation Agent & Metric Evaluation
**Goal**: An experiment runner agent can apply one atomic change per iteration, evaluate a deterministic metric, and return a structured result — while consuming the minimum possible tokens
**Depends on**: Phase 101
**Requirements**: EXEC-02, EXEC-03, EXEC-04, SELF-06, SELF-07, SELF-08, SELF-09
**Success Criteria** (what must be TRUE):
  1. `agents/pde-experiment-runner.md` exists and returns a structured JSON object per iteration with fields: `iteration`, `metric_value`, `metric_delta`, `status` (KEEP/DISCARD/CRASH), `description`, and `tokens_used`
  2. A commit attempt that modifies a file outside the declared mutable list is rejected before the commit fires, and the iteration retries without consuming a budget slot
  3. Metric evaluation runs the verify command via `spawnSync` with the configured timeout — a command that hangs past the timeout produces a CRASH status, not an infinite wait
  4. The runner defaults to Haiku for mutation attempts and only escalates to Sonnet after 3 consecutive boundary violations or crashes
  5. After iteration 1, the runner receives only the diff of current-best vs baseline rather than the full file, reducing per-iteration token consumption
  6. `results.jsonl` rows include a `tokens_used` field and REPORT.md includes total token cost and cost-per-improvement ratio
**Plans**: 2 plans

Plans:
- [x] 102-01-PLAN.md — Create experiment-runner.cjs library module with boundary check, metric eval, JSONL write, diff extraction
- [ ] 102-02-PLAN.md — Create pde-experiment-runner agent and wire pde-tools subcommands

### Phase 103: Orchestrator, Command & Circuit Breakers
**Goal**: The full experiment loop is orchestrated end-to-end — a user can invoke `/pde:optimize`, confirm the cost estimate, and the system iterates automatically with all stopping conditions enforced
**Depends on**: Phase 102
**Requirements**: BREAK-01, BREAK-02, BREAK-03, BREAK-04, BREAK-05, CMD-01, CMD-02, CMD-04, SELF-04, SELF-05
**Success Criteria** (what must be TRUE):
  1. `/pde:optimize experiment.md` starts an experiment loop: displays estimated token cost, waits for confirmation, then begins iterating with the pde-experiment-runner agent
  2. The experiment halts automatically when any of the 5 circuit breakers fires: iteration budget reached, time budget exceeded, K consecutive regressions, M iterations without improvement, or user declines the cost estimate gate
  3. After the loop completes, REPORT.md is generated listing iterations run, improvements kept, best metric achieved, files modified, and a diff summary of the best result vs baseline
  4. Promotion requires explicit user approval of the diff before the experiment branch is merged to main — declining cancels the merge and leaves the experiment branch intact
  5. A concurrency check at command startup detects active PDE sessions and warns the user before proceeding
**Plans**: 2 plans

Plans:
- [x] 103-01-PLAN.md — Create experiment-report.cjs with report generation, circuit breakers, cost estimate, and sonnet agent variant
- [ ] 103-02-PLAN.md — Create commands/optimize.md and workflows/optimize.md with full loop orchestration
