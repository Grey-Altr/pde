# WCAG Contrast Ratio Measurement Research

**Domain:** Visual accessibility metric for PDE v0.14 AutoResearch
**Researched:** 2026-03-23
**Overall confidence:** HIGH (W3C formulas are stable standards; implementation patterns well-established)

---

## 1. WCAG 2.1 AA Contrast Requirements

Source: [W3C WCAG 2.1 Success Criterion 1.4.3](https://www.w3.org/TR/WCAG21/#contrast-minimum) and [SC 1.4.11](https://www.w3.org/TR/WCAG21/#non-text-contrast)

### Thresholds

| Category | Minimum Ratio | Definition |
|----------|--------------|------------|
| Normal text | 4.5:1 | Text below 18pt (24px) regular or 14pt (18.66px) bold |
| Large text | 3:1 | Text at least 18pt (24px) regular OR 14pt (18.66px) bold |
| Non-text UI components | 3:1 | Buttons, form inputs, icons, graphical objects required to understand content |

### Large Text Definition

- **18pt regular** = 24px at default browser settings (1pt = 1.333px)
- **14pt bold** = 18.66px at font-weight >= 700
- For CJK fonts, equivalent visual sizes apply

### What Counts

- Text color against its immediate background
- Placeholder text in form inputs
- Link text (must also be distinguishable from surrounding text, but that is SC 1.4.1)
- UI component boundaries (button borders, input borders, toggle outlines)

### What Does NOT Count

- Disabled UI controls (WCAG explicitly exempts)
- Purely decorative text
- Brand logotypes
- Incidental text in photographs

## 2. W3C Relative Luminance Formula

Source: [W3C WCAG 2.1 G17 Technique](https://www.w3.org/WAI/WCAG21/Techniques/general/G17)

### Step 1: Normalize sRGB to 0-1

```
R_sRGB = R_8bit / 255
G_sRGB = G_8bit / 255
B_sRGB = B_8bit / 255
```

### Step 2: Linearize (undo gamma encoding)

```
if R_sRGB <= 0.04045:
    R_lin = R_sRGB / 12.92
else:
    R_lin = ((R_sRGB + 0.055) / 1.055) ^ 2.4

(same for G_lin, B_lin)
```

The threshold `0.04045` and the constants `12.92`, `0.055`, `1.055`, `2.4` come from the sRGB transfer function (IEC 61966-2-1).

### Step 3: Weighted sum for luminance

```
L = 0.2126 * R_lin + 0.7152 * G_lin + 0.0722 * B_lin
```

Coefficients reflect human perception: green contributes most to perceived brightness, blue the least.

### Step 4: Contrast ratio

```
contrast_ratio = (L_lighter + 0.05) / (L_darker + 0.05)
```

Where `L_lighter = max(L1, L2)` and `L_darker = min(L1, L2)`. The 0.05 offset prevents division by zero and accounts for ambient light.

Result range: 1:1 (identical) to 21:1 (black on white).

## 3. JavaScript Implementation

### Complete Relative Luminance and Contrast Ratio

```javascript
/**
 * Convert 8-bit sRGB channel to linear value.
 * Based on IEC 61966-2-1 (sRGB transfer function).
 */
function sRGBtoLinear(channel) {
  const s = channel / 255;
  return s <= 0.04045 ? s / 12.92 : Math.pow((s + 0.055) / 1.055, 2.4);
}

/**
 * Compute relative luminance per WCAG 2.1 definition.
 * @param {number} r - Red 0-255
 * @param {number} g - Green 0-255
 * @param {number} b - Blue 0-255
 * @returns {number} Luminance 0-1
 */
function relativeLuminance(r, g, b) {
  return 0.2126 * sRGBtoLinear(r) + 0.7152 * sRGBtoLinear(g) + 0.0722 * sRGBtoLinear(b);
}

/**
 * Compute WCAG 2.1 contrast ratio between two colors.
 * @param {number[]} fg - [r, g, b] foreground color (0-255 each)
 * @param {number[]} bg - [r, g, b] background color (0-255 each)
 * @returns {number} Contrast ratio (1.0 to 21.0)
 */
function contrastRatio(fg, bg) {
  const L1 = relativeLuminance(...fg);
  const L2 = relativeLuminance(...bg);
  const lighter = Math.max(L1, L2);
  const darker = Math.min(L1, L2);
  return (lighter + 0.05) / (darker + 0.05);
}
```

### CSS Color Parsing (browser context)

```javascript
/**
 * Parse any CSS color string to [r, g, b, a] using a canvas.
 * Works with: hex, rgb(), rgba(), hsl(), hsla(), oklch(), named colors.
 * Must run in browser context (needs OffscreenCanvas or <canvas>).
 */
function parseColor(colorStr) {
  if (!colorStr || colorStr === 'transparent') return [0, 0, 0, 0];

  // Use canvas 2D context as a universal color parser
  const ctx = document.createElement('canvas').getContext('2d');
  ctx.fillStyle = colorStr;
  ctx.fillRect(0, 0, 1, 1);
  const [r, g, b, a] = ctx.getImageData(0, 0, 1, 1).data;
  return [r, g, b, a / 255];
}

/**
 * Alternative: parse rgb()/rgba() string directly (faster, no canvas).
 */
function parseRGBA(str) {
  if (!str || str === 'transparent') return [0, 0, 0, 0];
  // getComputedStyle always returns rgb() or rgba() in modern browsers
  const m = str.match(/rgba?\((\d+),\s*(\d+),\s*(\d+)(?:,\s*([\d.]+))?\)/);
  if (!m) return [0, 0, 0, 0];
  return [+m[1], +m[2], +m[3], m[4] !== undefined ? +m[4] : 1];
}
```

### Effective Background Color Resolution

When `getComputedStyle(el).backgroundColor` returns `transparent` or `rgba(0,0,0,0)`, the element has no painted background. Must walk up the DOM tree.

```javascript
/**
 * Resolve the effective background color of an element by walking
 * up the DOM tree, compositing semi-transparent layers.
 *
 * @param {Element} el - Target element
 * @returns {number[]} [r, g, b] effective background (0-255 each)
 */
function getEffectiveBackground(el) {
  const layers = []; // collect from element up to root

  let current = el;
  while (current && current !== document) {
    const bg = window.getComputedStyle(current).backgroundColor;
    const [r, g, b, a] = parseRGBA(bg);

    if (a > 0) {
      layers.push([r, g, b, a]);
      // If fully opaque, no need to look further up
      if (a >= 1) break;
    }
    current = current.parentElement;
  }

  // If no backgrounds found, assume white (browser default)
  if (layers.length === 0) return [255, 255, 255];

  // Composite from back (parent) to front (child)
  // Start with white as the canvas base
  let base = [255, 255, 255];
  for (let i = layers.length - 1; i >= 0; i--) {
    const [r, g, b, a] = layers[i];
    base = [
      Math.round(r * a + base[0] * (1 - a)),
      Math.round(g * a + base[1] * (1 - a)),
      Math.round(b * a + base[2] * (1 - a)),
    ];
  }
  return base;
}
```

**Alpha compositing formula** (source-over): `result = src * alpha + dst * (1 - alpha)` per channel.

### Determining if Text is "Large"

```javascript
/**
 * Check if an element's text qualifies as "large text" per WCAG.
 * Large = 18pt+ (24px+) regular, or 14pt+ (18.66px+) bold.
 */
function isLargeText(el) {
  const style = window.getComputedStyle(el);
  const size = parseFloat(style.fontSize); // in px
  const weight = parseInt(style.fontWeight, 10) || (
    style.fontWeight === 'bold' ? 700 : 400
  );
  // 18pt = 24px, 14pt = 18.66px
  return size >= 24 || (size >= 18.66 && weight >= 700);
}
```

## 4. APCA vs WCAG 2.x Contrast

Sources: [APCA in a Nutshell](https://git.apcacontrast.com/documentation/APCA_in_a_Nutshell.html), [Why APCA](https://git.apcacontrast.com/documentation/WhyAPCA.html), [W3C WCAG 3 Issue #29](https://github.com/w3c/wcag3/issues/29)

### Key Differences

| Aspect | WCAG 2.x | APCA |
|--------|---------|------|
| Metric | Ratio (1:1 to 21:1) | Lc value (0 to ~107) |
| Polarity-aware | No (same ratio for dark-on-light and light-on-dark) | Yes (text-on-bg vs bg-on-text produce different Lc) |
| Font-size/weight aware | Only large vs normal (binary) | Full lookup table across size x weight |
| Dark mode accuracy | Poor (overstates contrast near black) | Good (perceptually uniform across light/dark) |
| Standard status | W3C Recommendation (WCAG 2.1) | Candidate for WCAG 3.0 (not yet normative) |

### APCA Lc Thresholds

| Lc Value | Use Case |
|----------|----------|
| Lc 90 | Preferred for fluent body text columns (18px/300w or 14px/400w min) |
| Lc 75 | Minimum for body text (24px/300w, 18px/400w, 16px/500w, 14px/700w) |
| Lc 60 | Non-body content text; larger sizes required |
| Lc 45 | Headlines, large text, pictogram details |
| Lc 30 | Absolute minimum for spot-readable text, semantic icons |
| Lc 15 | Non-semantic non-text that must be discernible |

### PDE's Current APCA Usage

PDE's `system.md` already generates APCA-annotated semantic tokens:

```css
--color-text-primary: var(--color-neutral-900)   /* |Lc| ~95 on white bg */
--color-text-secondary: var(--color-neutral-600)  /* |Lc| ~68 on white bg */
--color-text-muted: var(--color-neutral-400)      /* |Lc| ~45 on white bg */
```

### Recommendation for contrast-metric.cjs

**Use WCAG 2.x contrast ratio as the primary metric.** Rationale:

1. WCAG 2.1 AA is the legal and compliance standard today. APCA is not yet normative.
2. The metric script needs a binary pass/fail per element. WCAG 2.x has clear thresholds (4.5:1 / 3:1). APCA requires a font-size x weight lookup table that makes pass/fail more complex.
3. PDE already annotates Lc values in token comments. A future `bin/apca-metric.cjs` can be added separately.
4. The WCAG 2.x formula is self-contained (no external library). APCA's full algorithm (apca-w3 npm package) adds a dependency.

**Bridge strategy:** The token test page can include both WCAG ratio and APCA Lc in its output data attributes, letting experiments optimize for either metric. But the primary `contrast-metric.cjs` should output WCAG pass count.

## 5. Complete browser_evaluate Script for contrast-metric.cjs

This is the script that runs inside `page.evaluate()` (or equivalent Playwright MCP `browser_evaluate`).

```javascript
(() => {
  // --- Core WCAG functions ---

  function sRGBtoLinear(c) {
    const s = c / 255;
    return s <= 0.04045 ? s / 12.92 : Math.pow((s + 0.055) / 1.055, 2.4);
  }

  function luminance(r, g, b) {
    return 0.2126 * sRGBtoLinear(r) + 0.7152 * sRGBtoLinear(g) + 0.0722 * sRGBtoLinear(b);
  }

  function contrastRatio(fg, bg) {
    const L1 = luminance(...fg);
    const L2 = luminance(...bg);
    const lighter = Math.max(L1, L2);
    const darker = Math.min(L1, L2);
    return (lighter + 0.05) / (darker + 0.05);
  }

  // --- Color parsing ---

  function parseRGBA(str) {
    if (!str || str === 'transparent') return [0, 0, 0, 0];
    const m = str.match(/rgba?\(\s*([\d.]+),\s*([\d.]+),\s*([\d.]+)(?:\s*[,/]\s*([\d.]+))?\s*\)/);
    if (!m) return [0, 0, 0, 0];
    return [Math.round(+m[1]), Math.round(+m[2]), Math.round(+m[3]), m[4] !== undefined ? +m[4] : 1];
  }

  // --- Effective background resolution ---

  function getEffectiveBg(el) {
    const layers = [];
    let cur = el;
    while (cur && cur !== document) {
      const bg = window.getComputedStyle(cur).backgroundColor;
      const [r, g, b, a] = parseRGBA(bg);
      if (a > 0) {
        layers.push([r, g, b, a]);
        if (a >= 1) break;
      }
      cur = cur.parentElement;
    }
    if (layers.length === 0) return [255, 255, 255];
    let base = [255, 255, 255];
    for (let i = layers.length - 1; i >= 0; i--) {
      const [r, g, b, a] = layers[i];
      base = [
        Math.round(r * a + base[0] * (1 - a)),
        Math.round(g * a + base[1] * (1 - a)),
        Math.round(b * a + base[2] * (1 - a)),
      ];
    }
    return base;
  }

  // --- Large text check ---

  function isLargeText(el) {
    const style = window.getComputedStyle(el);
    const size = parseFloat(style.fontSize);
    const weight = parseInt(style.fontWeight, 10) || (style.fontWeight === 'bold' ? 700 : 400);
    return size >= 24 || (size >= 18.66 && weight >= 700);
  }

  // --- Main scan ---

  // Select all elements likely to contain visible text
  const textSelectors = 'h1,h2,h3,h4,h5,h6,p,span,a,li,td,th,label,button,input,textarea,select,figcaption,blockquote,cite,code,pre,small,strong,em,mark,del,ins,sub,sup,abbr,time,summary,legend,dt,dd';
  const elements = document.querySelectorAll(textSelectors);

  let pass = 0;
  let fail = 0;
  let skip = 0;

  for (const el of elements) {
    // Skip hidden or empty elements
    const style = window.getComputedStyle(el);
    if (style.display === 'none' || style.visibility === 'hidden' || style.opacity === '0') {
      skip++;
      continue;
    }
    // Skip elements with no direct text content
    const hasDirectText = Array.from(el.childNodes).some(
      n => n.nodeType === Node.TEXT_NODE && n.textContent.trim().length > 0
    );
    if (!hasDirectText) {
      skip++;
      continue;
    }

    const fg = parseRGBA(style.color);
    const bg = getEffectiveBg(el);
    const ratio = contrastRatio([fg[0], fg[1], fg[2]], bg);
    const threshold = isLargeText(el) ? 3.0 : 4.5;

    if (ratio >= threshold) {
      pass++;
    } else {
      fail++;
    }
  }

  return { pass, fail, skip, total: pass + fail };
})();
```

### Edge Cases Handled

| Edge Case | How Handled |
|-----------|-------------|
| Transparent background | DOM tree walk with alpha compositing; defaults to white |
| `rgba()` semi-transparent backgrounds | Source-over compositing per channel |
| Hidden elements (`display:none`, `visibility:hidden`, `opacity:0`) | Skipped |
| Empty elements (no text nodes) | Skipped |
| Large text (18pt+ or 14pt+ bold) | Uses 3:1 threshold instead of 4.5:1 |
| CSS gradients | `getComputedStyle` returns the first color stop; for full accuracy would need canvas sampling, but first-stop is a reasonable approximation for metric purposes |
| `oklch()` / `hsl()` / named colors | `getComputedStyle` normalizes all to `rgb()`/`rgba()` in modern browsers |
| SVG text | Not selected by the CSS selector list; `<text>` elements need separate SVG handling (recommend deferring to a future SVG-specific metric) |
| Pseudo-elements (`::before`, `::after`) | Not directly scannable via `querySelectorAll`; would need `getComputedStyle(el, '::before')` for color, but pseudo-element text is rare in design token test pages |
| White text on white background | Correctly computes 1:1 ratio, fails threshold |
| Form input placeholders | `input`/`textarea` selected; placeholder color requires `::placeholder` pseudo-element (deferred, same as pseudo-elements above) |

### What contrast-metric.cjs Returns

Per VMET-06 contract: exit 0, print single numeric value to stdout.

**Return value = `pass` count.** Higher is better (`direction: max` in experiment template).

The `{ pass, fail, skip, total }` object from `browser_evaluate` gets destructured; the script prints `pass` to stdout.

## 6. Token Test Page Design (for TEXP-02)

### Purpose

The token test page (`references/experiments/token-test-page.html`) applies DTCG-generated CSS custom properties to representative UI elements. `contrast-metric.cjs` renders this page and measures how many text/background pairs pass WCAG AA.

### Required UI Elements

The test page must cover every semantic color token assignment that system.md generates:

| Section | Elements | Tokens Tested |
|---------|----------|---------------|
| Typography | h1-h6, body paragraph, small text, muted text | `--color-text-primary`, `--color-text-secondary`, `--color-text-muted` on `--color-bg-default` |
| Buttons | Primary, secondary, ghost, destructive | `--color-primary-*` on button backgrounds, text on primary fill |
| Cards | Card with title, body text, footer link | `--color-bg-surface`, `--color-bg-elevated` with text tokens |
| Forms | Input with label, placeholder, disabled state | `--color-text-primary` on `--color-bg-default`, border contrast |
| Badges/Tags | Success, warning, error, info | Semantic status colors as background with text overlay |
| Navigation | Nav links, active state, hover state | Text tokens on background tokens |
| Alerts | Info, success, warning, error banners | Status background + text combinations |
| Dark mode toggle | Duplicate of above sections in `[data-theme="dark"]` | Dark mode semantic tokens |

### Applying DTCG Tokens as CSS Custom Properties

PDE's `system.md` produces a `SYS-tokens.json` in DTCG format and a derived `SYS-tokens.css` with custom properties. The test page approach:

### Dark Mode Testing

Two approaches (use both):

1. **Attribute toggle:** Render once with `data-theme="light"`, measure. Then inject `document.documentElement.setAttribute('data-theme', 'dark')`, re-measure.
2. **Separate measurement:** Return `{ light: { pass, fail }, dark: { pass, fail } }`. The metric script sums both pass counts for the final number.

For v0.14 MVP: render light mode only. Dark mode adds complexity (double render) and can be a follow-up experiment variant.

### Token CSS Injection Strategy

`contrast-metric.cjs` receives a file path (the token CSS or the HTML test page). Implementation options:

1. **Static HTML with placeholder:** Test page has `<!-- TOKEN_CSS -->` placeholder; script injects the generated CSS inline before serving.
2. **Serve directory:** Use `npx serve` on the design directory, test page references `SYS-tokens.css` via relative path.
3. **Inline injection via evaluate:** Navigate to test page, then `browser_evaluate` to inject a `<style>` block with token values.

**Recommended:** Option 2 (serve directory). It matches the PLAY-05 fallback pattern already planned for wireframe rendering, and keeps the test page a plain HTML file that can also be opened manually for debugging.

## 7. Pitfalls and Edge Cases

### Critical: getComputedStyle Returns Resolved Values

Modern browsers (Chrome 90+, Firefox 89+, Safari 15+) resolve `oklch()`, `hsl()`, `color()` to `rgb()`/`rgba()` in `getComputedStyle`. This means the `parseRGBA` function works universally. **Do not attempt to parse oklch/hsl directly from computed styles.**

Confidence: HIGH. Verified behavior in Chromium (which Playwright uses).

### Critical: Gradient Backgrounds

`getComputedStyle(el).backgroundColor` returns the solid color, NOT the gradient. If `background` or `background-image` contains a gradient, `backgroundColor` may be `transparent` while the visual background is the gradient.

**Mitigation for v0.14:** The token test page should use only solid backgrounds (no gradients). This is a design constraint on the test page, not a limitation of the metric script. Design token systems use semantic solid colors, not gradients, for their base assignments.

### Moderate: Overlapping Elements

Elements with `position: absolute/fixed` may visually overlap other content. The DOM tree walk only finds ancestor backgrounds, not siblings that visually sit behind an element.

**Mitigation:** The token test page uses simple flow layout. No absolute positioning. This is a test page constraint.

### Moderate: CSS `color-scheme` and Forced Colors

`prefers-color-scheme` media queries and `forced-colors` mode can alter computed colors. Playwright's headless Chromium uses `prefers-color-scheme: light` by default.

**Mitigation:** Explicitly set `color-scheme: light` on the test page `<html>` element. This prevents browser dark mode injection.

### Minor: Web Fonts and Font Weight

If web fonts haven't loaded when measurement runs, `font-weight` may differ from intended (fallback font may not support the same weight). This affects the large-text threshold check.

**Mitigation:** Use `page.waitForLoadState('networkidle')` before running `browser_evaluate`. Or use system fonts in the test page (which is what PDE's token system defaults to: `system-ui, sans-serif`).

## 8. Implementation Plan for contrast-metric.cjs

### Contract

```
Usage: node bin/contrast-metric.cjs <path-to-html-or-css>
Exit:  0 always (non-zero = CRASH per _evalMetric contract)
Stdout: single integer (pass count)
```

### Pseudocode

```
1. Parse argv[1] as file path
2. If Playwright MCP not available: print "0", exit 0 (graceful degradation per VMET-07)
3. Determine if input is HTML (test page) or CSS (tokens file)
   - If CSS: use bundled token-test-page.html template, inject CSS path
   - If HTML: use directly
4. Start local server: `npx serve <directory> -p 0 --no-clipboard`
   - Capture assigned port from stdout
5. Navigate Playwright to `http://localhost:{port}/token-test-page.html`
6. Wait for networkidle
7. Run browser_evaluate with the contrast scanning script from Section 5
8. Extract `pass` from result
9. Print pass count to stdout
10. Kill local server, exit 0
```

### No External Dependencies

The entire WCAG contrast calculation is ~40 lines of vanilla JS. No npm packages needed. This aligns with PDE's zero-dependency philosophy.
