# Visual DOM Quality Metrics Research

**Domain:** Browser-based visual quality scoring for HTML wireframes/mockups
**Researched:** 2026-03-23
**Overall Confidence:** HIGH (DOM APIs are stable, patterns well-established)

## Executive Summary

All four metric areas (DOM structure scoring, responsive compliance, accessibility violation counting, and contrast checking) are fully implementable using standard Web APIs available inside Playwright MCP's `browser_evaluate` tool. No external libraries are required for basic scoring -- pure `document.querySelectorAll`, `getComputedStyle`, and `getBoundingClientRect` cover every measurement. For accessibility, axe-core injection via `addScriptTag` before `browser_evaluate` provides industrial-strength violation detection, but a lightweight custom checker (counting missing alt text, broken heading hierarchy, missing landmarks, missing form labels) is sufficient for the experiment runner's numeric scoring needs and avoids CDN dependencies.

The key architectural decision: **keep each metric as a single self-contained JavaScript function string** that `browser_evaluate` executes. This avoids file-serving complexity, keeps the metric scripts portable, and matches the existing `_evalMetric` contract (exit 0, print number to stdout).

## 1. DOM Structure Scoring

**Confidence: HIGH** -- All APIs are standard DOM Level 2+, universally supported.

### Available APIs

All measurements use `document.querySelectorAll()` and basic property access:

```javascript
// Element diversity
const headings = document.querySelectorAll('h1,h2,h3,h4,h5,h6');
const paragraphs = document.querySelectorAll('p');
const lists = document.querySelectorAll('ul,ol,dl');
const images = document.querySelectorAll('img,picture,svg');
const buttons = document.querySelectorAll('button,[role="button"]');
const forms = document.querySelectorAll('form');
const links = document.querySelectorAll('a[href]');
const inputs = document.querySelectorAll('input,select,textarea');

// Landmarks (HTML5 semantic + ARIA)
const landmarks = document.querySelectorAll(
  'header,nav,main,footer,aside,section,article,' +
  '[role="banner"],[role="navigation"],[role="main"],' +
  '[role="contentinfo"],[role="complementary"],[role="region"]'
);

// Interactive elements
const interactive = document.querySelectorAll(
  'a[href],button,[role="button"],input,select,textarea,' +
  '[tabindex]:not([tabindex="-1"])'
);
```

### Heading Hierarchy Validation

Check that heading levels don't skip (h1 -> h3 without h2):

```javascript
function scoreHeadingHierarchy() {
  const headings = [...document.querySelectorAll('h1,h2,h3,h4,h5,h6')];
  if (headings.length === 0) return 0;

  let score = 10; // base points for having any headings
  let prevLevel = 0;
  let skips = 0;

  for (const h of headings) {
    const level = parseInt(h.tagName[1]);
    if (prevLevel > 0 && level > prevLevel + 1) {
      skips++; // skipped a level (e.g., h1 -> h3)
    }
    prevLevel = level;
  }

  // Bonus for h1 presence
  const hasH1 = headings.some(h => h.tagName === 'H1');
  if (hasH1) score += 5;

  // Penalty for skips
  score -= skips * 3;

  // Bonus for depth (using h3+ shows hierarchy)
  const maxLevel = Math.max(...headings.map(h => parseInt(h.tagName[1])));
  if (maxLevel >= 3) score += 5;

  return Math.max(0, Math.min(20, score));
}
```

### Whitespace Ratio Heuristic

The ratio of text-containing elements to pure structural/wrapper containers. Higher ratio = more content, less empty chrome:

```javascript
function scoreWhitespaceRatio() {
  const allElements = document.body.querySelectorAll('*');
  let textContaining = 0;
  let totalVisible = 0;

  for (const el of allElements) {
    const style = getComputedStyle(el);
    if (style.display === 'none' || style.visibility === 'hidden') continue;
    totalVisible++;

    // Check if element has direct text content (not just child element text)
    for (const node of el.childNodes) {
      if (node.nodeType === 3 && node.textContent.trim().length > 0) {
        textContaining++;
        break;
      }
    }
  }

  if (totalVisible === 0) return 0;
  const ratio = textContaining / totalVisible;
  // Ideal ratio: 0.3-0.5 (30-50% of elements contain direct text)
  // Too low = empty wrapper divitis; too high = flat structure
  if (ratio >= 0.25 && ratio <= 0.55) return 15;
  if (ratio >= 0.15 && ratio <= 0.65) return 10;
  return 5;
}
```

### Recommended Scoring Weights (0-100 scale)

| Dimension | Weight (Wireframe) | Weight (Mockup) | Rationale |
|-----------|-------------------|-----------------|-----------|
| Element diversity (unique tag types used) | 15 | 10 | Wireframes need structural variety |
| Heading hierarchy (depth + correctness) | 20 | 15 | Critical for information architecture |
| Landmark count | 20 | 15 | Semantic structure signal |
| Interactive element count | 15 | 25 | Mockups must show interactivity |
| Whitespace ratio | 15 | 10 | Content density signal |
| Total element count (min threshold) | 15 | 10 | Minimum complexity signal |
| Image/media presence | 0 | 15 | Mockups should have visual assets |

**Wireframe scoring emphasizes structure** (headings, landmarks, element diversity) because wireframes define information architecture. **Mockup scoring emphasizes interactivity and polish** (buttons, inputs, images) because mockups demonstrate the interactive experience.

### Combined Score Function

```javascript
function computeDOMScore(mode = 'wireframe') {
  const weights = mode === 'mockup'
    ? { diversity: 10, headings: 15, landmarks: 15, interactive: 25,
        whitespace: 10, elementCount: 10, media: 15 }
    : { diversity: 15, headings: 20, landmarks: 20, interactive: 15,
        whitespace: 15, elementCount: 15, media: 0 };

  let score = 0;

  // Element diversity: count unique tag names used
  const allTags = new Set(
    [...document.body.querySelectorAll('*')].map(e => e.tagName)
  );
  const diversityScore = Math.min(weights.diversity,
    (allTags.size / 15) * weights.diversity  // 15+ unique tags = full marks
  );
  score += diversityScore;

  // Heading hierarchy
  score += scoreHeadingHierarchy() * (weights.headings / 20);

  // Landmarks
  const landmarkCount = document.querySelectorAll(
    'header,nav,main,footer,aside,section,article,' +
    '[role="banner"],[role="navigation"],[role="main"],' +
    '[role="contentinfo"],[role="complementary"]'
  ).length;
  score += Math.min(weights.landmarks,
    (landmarkCount / 5) * weights.landmarks  // 5+ landmarks = full marks
  );

  // Interactive elements
  const interactiveCount = document.querySelectorAll(
    'a[href],button,[role="button"],input,select,textarea'
  ).length;
  score += Math.min(weights.interactive,
    (interactiveCount / 8) * weights.interactive  // 8+ = full marks
  );

  // Whitespace ratio
  score += scoreWhitespaceRatio() * (weights.whitespace / 15);

  // Total element count (minimum complexity)
  const totalElements = document.body.querySelectorAll('*').length;
  score += Math.min(weights.elementCount,
    (totalElements / 50) * weights.elementCount  // 50+ elements = full marks
  );

  // Media presence (mockup only)
  if (weights.media > 0) {
    const mediaCount = document.querySelectorAll('img,picture,svg,video').length;
    score += Math.min(weights.media,
      (mediaCount / 3) * weights.media  // 3+ media = full marks
    );
  }

  return Math.round(Math.max(0, Math.min(100, score)));
}
```

## 2. Responsive Compliance Measurement

**Confidence: HIGH** -- `scrollWidth`, `clientWidth`, `getBoundingClientRect` are universally available.

### Horizontal Overflow Detection

The fundamental check: `element.scrollWidth > element.clientWidth`. Apply to `document.documentElement` and `document.body` for page-level overflow, plus key containers:

```javascript
function detectHorizontalOverflow() {
  const violations = [];

  // Page-level overflow
  if (document.documentElement.scrollWidth > document.documentElement.clientWidth) {
    violations.push({
      element: 'html',
      overflow: document.documentElement.scrollWidth - document.documentElement.clientWidth
    });
  }

  // Check all direct children of body and major containers
  const containers = document.querySelectorAll(
    'body > *, main, section, article, .container, [class*="wrapper"]'
  );
  for (const el of containers) {
    if (el.scrollWidth > el.clientWidth + 1) { // +1 for rounding tolerance
      violations.push({
        element: el.tagName + (el.className ? '.' + el.className.split(' ')[0] : ''),
        overflow: el.scrollWidth - el.clientWidth
      });
    }
  }

  return violations;
}
```

### Content Stacking Violation Detection

At mobile breakpoints, flex/grid children should stack vertically. Detect side-by-side elements that should have stacked:

```javascript
function detectStackingViolations(minWidth) {
  // Only relevant at mobile breakpoints (< 768px)
  if (minWidth >= 768) return [];

  const violations = [];
  const rows = document.querySelectorAll(
    '[class*="row"], [class*="grid"], [class*="flex"], ' +
    '[style*="display: flex"], [style*="display: grid"]'
  );

  for (const row of rows) {
    const children = [...row.children].filter(c => {
      const s = getComputedStyle(c);
      return s.display !== 'none' && s.position !== 'absolute';
    });

    if (children.length < 2) continue;

    // Check if children are side-by-side (same top offset)
    const rects = children.map(c => c.getBoundingClientRect());
    const sameRow = rects.filter((r, i) =>
      i > 0 && Math.abs(r.top - rects[0].top) < 5
    );

    if (sameRow.length > 0 && rects[0].width < 300) {
      // Multiple items on same row AND each is narrow = likely should stack
      violations.push({
        element: row.tagName + (row.className ? '.' + row.className.split(' ')[0] : ''),
        childCount: children.length,
        issue: 'side-by-side at narrow viewport'
      });
    }
  }

  return violations;
}
```

### Touch Target Size Measurement

WCAG 2.5.8 (Level AA) requires 24x24 CSS pixels minimum. Best practice (and Android guidelines) is 48x48. Use 44x44 as the scoring threshold (Apple HIG, WCAG 2.5.5 Level AAA):

```javascript
function measureTouchTargets(minSize = 44) {
  const interactive = document.querySelectorAll(
    'a[href], button, [role="button"], input:not([type="hidden"]), ' +
    'select, textarea, [tabindex]:not([tabindex="-1"])'
  );

  let passing = 0;
  let failing = 0;
  const failures = [];

  for (const el of interactive) {
    const rect = el.getBoundingClientRect();
    if (rect.width === 0 && rect.height === 0) continue; // hidden

    if (rect.width >= minSize && rect.height >= minSize) {
      passing++;
    } else {
      failing++;
      failures.push({
        element: el.tagName + (el.textContent || '').trim().slice(0, 20),
        width: Math.round(rect.width),
        height: Math.round(rect.height)
      });
    }
  }

  return { passing, failing, failures };
}
```

### Media Query Function Verification

Cannot directly read `@media` rules from `browser_evaluate` without parsing stylesheets. Instead, use the practical approach: **resize the viewport and compare computed styles**. Playwright MCP provides `browser_resize` for this. The metric script should:

1. Render at 1280px, capture layout data via `browser_evaluate`
2. `browser_resize` to 768px, capture again
3. `browser_resize` to 375px, capture again
4. Compare: if computed values are identical at all breakpoints, media queries are non-functional

```javascript
// Run at each breakpoint, compare results
function captureLayoutSignature() {
  const body = document.body;
  const main = document.querySelector('main') || body;
  const nav = document.querySelector('nav');

  return {
    bodyWidth: body.clientWidth,
    mainWidth: main.clientWidth,
    mainPadding: getComputedStyle(main).padding,
    navDisplay: nav ? getComputedStyle(nav).display : null,
    navFlexDirection: nav ? getComputedStyle(nav).flexDirection : null,
    fontSize: getComputedStyle(body).fontSize,
    gridCols: getComputedStyle(main).gridTemplateColumns || null,
    overflowing: document.documentElement.scrollWidth > document.documentElement.clientWidth,
  };
}
```

### Responsive Scoring (per breakpoint)

| Check | Points | Pass Criteria |
|-------|--------|---------------|
| No horizontal overflow | 30 | `scrollWidth <= clientWidth` |
| Touch targets >= 44px | 25 | All interactive elements meet minimum |
| Content stacks on mobile | 20 | No side-by-side violations at 375px |
| Layout changes between breakpoints | 15 | Computed styles differ at 1280 vs 375 |
| Font size readable at mobile | 10 | `fontSize >= 14px` at 375px |

Total per breakpoint: 100. Final score = average across 3 breakpoints (375, 768, 1280).

**Important:** The metric script must orchestrate the resize + evaluate sequence, not do it in a single evaluate call. The CJS script calls `browser_resize` then `browser_evaluate` three times.

## 3. AOM Violation Counting (Accessibility)

**Confidence: HIGH** -- DOM queries for a11y patterns are straightforward. Contrast detection via `getComputedStyle` is MEDIUM confidence (color parsing has edge cases).

### Approach: Custom Lightweight Checker vs axe-core

**Recommendation: Use custom lightweight checker for metric scoring.** Rationale:

- axe-core requires CDN injection (`addScriptTag`) or bundling the 300KB+ library
- axe-core returns rich objects, but we only need a violation count integer
- Custom checks are faster (single DOM traversal vs axe-core's full audit)
- Custom checks are deterministic (no rule version drift)
- axe-core is overkill when the experiment runner only needs a number

Reserve axe-core injection for the `A11Y-01`/`A11Y-02` critique workflow integration where rich violation descriptions matter.

### Violation Checks

#### Missing Alt Text on Images

```javascript
function countMissingAlt() {
  const images = document.querySelectorAll('img');
  let violations = 0;
  for (const img of images) {
    const alt = img.getAttribute('alt');
    // Missing alt entirely (not same as alt="" which is intentional for decorative)
    if (alt === null) violations++;
  }
  return violations;
}
```

**Note:** `alt=""` is valid for decorative images per WCAG. Only count `alt === null` (attribute absent) as a violation.

#### Broken Heading Hierarchy

```javascript
function countHeadingSkips() {
  const headings = [...document.querySelectorAll('h1,h2,h3,h4,h5,h6')];
  let violations = 0;
  let prevLevel = 0;

  for (const h of headings) {
    const level = parseInt(h.tagName[1]);
    if (prevLevel > 0 && level > prevLevel + 1) {
      violations++; // e.g., h1 followed by h3
    }
    prevLevel = level;
  }

  // No h1 at all is a violation
  if (headings.length > 0 && !headings.some(h => h.tagName === 'H1')) {
    violations++;
  }

  return violations;
}
```

#### Missing Landmarks

```javascript
function countMissingLandmarks() {
  let violations = 0;
  const checks = [
    { selector: 'main,[role="main"]', name: 'main' },
    { selector: 'nav,[role="navigation"]', name: 'navigation' },
    { selector: 'header,[role="banner"]', name: 'banner/header' },
  ];

  for (const check of checks) {
    if (!document.querySelector(check.selector)) {
      violations++;
    }
  }

  return violations;
}
```

#### Missing Form Labels

```javascript
function countMissingFormLabels() {
  const inputs = document.querySelectorAll(
    'input:not([type="hidden"]):not([type="submit"]):not([type="button"]), ' +
    'select, textarea'
  );
  let violations = 0;

  for (const input of inputs) {
    const hasLabel = input.id && document.querySelector(`label[for="${input.id}"]`);
    const hasAriaLabel = input.getAttribute('aria-label');
    const hasAriaLabelledBy = input.getAttribute('aria-labelledby');
    const wrappedInLabel = input.closest('label');

    if (!hasLabel && !hasAriaLabel && !hasAriaLabelledBy && !wrappedInLabel) {
      violations++;
    }
  }

  return violations;
}
```

#### Color Contrast (via getComputedStyle)

**Confidence: MEDIUM** -- Works for solid colors. Fails for gradients, background images, opacity stacking, and inherited backgrounds.

```javascript
function parseRGB(colorStr) {
  // getComputedStyle always returns rgb() or rgba() format
  const match = colorStr.match(/rgba?\((\d+),\s*(\d+),\s*(\d+)/);
  if (!match) return null;
  return [parseInt(match[1]), parseInt(match[2]), parseInt(match[3])];
}

function luminance(rgb) {
  const [r, g, b] = rgb.map(v => {
    v /= 255;
    return v <= 0.03928 ? v / 12.92 : Math.pow((v + 0.055) / 1.055, 2.4);
  });
  return 0.2126 * r + 0.7152 * g + 0.0722 * b;
}

function contrastRatio(rgb1, rgb2) {
  const l1 = luminance(rgb1);
  const l2 = luminance(rgb2);
  const lighter = Math.max(l1, l2);
  const darker = Math.min(l1, l2);
  return (lighter + 0.05) / (darker + 0.05);
}

function countContrastViolations() {
  // Check all text-containing elements
  const textElements = document.querySelectorAll(
    'p, h1, h2, h3, h4, h5, h6, span, a, li, td, th, label, button'
  );
  let violations = 0;

  for (const el of textElements) {
    if (!el.textContent.trim()) continue;
    const style = getComputedStyle(el);
    if (style.display === 'none' || style.visibility === 'hidden') continue;

    const fg = parseRGB(style.color);
    const bg = parseRGB(style.backgroundColor);

    if (!fg || !bg) continue;

    // Skip transparent backgrounds (rgba with 0 alpha)
    if (style.backgroundColor.includes('rgba') && style.backgroundColor.includes(', 0)')) {
      continue; // Would need to walk up the DOM tree for actual background
    }

    const ratio = contrastRatio(fg, bg);
    const fontSize = parseFloat(style.fontSize);
    const isBold = parseInt(style.fontWeight) >= 700;
    const isLargeText = fontSize >= 24 || (fontSize >= 18.66 && isBold);

    const threshold = isLargeText ? 3.0 : 4.5; // WCAG AA

    if (ratio < threshold) {
      violations++;
    }
  }

  return violations;
}
```

**Known limitations of getComputedStyle-based contrast checking:**
- Cannot resolve inherited backgrounds (must walk up DOM tree)
- Cannot handle background images or gradients
- Cannot handle overlapping elements or opacity
- `rgba(0,0,0,0)` (transparent) is common default -- must skip or walk parents
- For PDE's use case (generated wireframes/mockups with explicit backgrounds), this is acceptable

#### Combined Violation Count Function

```javascript
function countAllA11yViolations() {
  return (
    countMissingAlt() +
    countHeadingSkips() +
    countMissingLandmarks() +
    countMissingFormLabels() +
    countContrastViolations()
  );
}
```

Return value: integer. Lower is better. The experiment runner uses `direction: min`.

## 4. JavaScript Patterns for browser_evaluate

**Confidence: HIGH** -- Playwright MCP's evaluate tool is well-documented.

### Playwright MCP browser_evaluate API

**Tool name:** `browser_evaluate`
**Parameters:**
- `function` (required, string): JavaScript function as a string, either `() => { ... }` or `(element) => { ... }` format
- `element` (optional): Human-readable element description for scoped evaluation
- `ref` (optional): Element reference from page snapshot

**Return:** The serialized return value of the function. Must be JSON-serializable: strings, numbers, booleans, arrays, plain objects. No DOM elements, functions, Symbols, or circular references.

### What APIs Are Available Inside browser_evaluate

Everything in the page's global scope:

| API | Available | Notes |
|-----|-----------|-------|
| `document.querySelectorAll` | Yes | Primary DOM query method |
| `document.querySelector` | Yes | Single element query |
| `getComputedStyle(el)` | Yes | Read resolved CSS values |
| `el.getBoundingClientRect()` | Yes | Element position and size |
| `el.scrollWidth / clientWidth` | Yes | Overflow detection |
| `el.getAttribute()` | Yes | Read HTML attributes |
| `el.childNodes / children` | Yes | DOM traversal |
| `window.innerWidth / innerHeight` | Yes | Viewport dimensions |
| `performance.now()` | Yes | Timing measurements |
| `console.log` | Yes | Debugging (captured by `browser_console_messages`) |
| `fetch()` | Yes | But avoid -- adds network dependency |
| `localStorage / sessionStorage` | Yes | But not useful for metrics |

### Serialization Constraints

**Must return:** `string | number | boolean | null | Array | plain Object`

**Must NOT return:** DOM elements, NodeLists (wrap in `[...nodeList].map()`), functions, Symbols, Map/Set (convert to Array/Object first), circular structures.

Pattern for returning DOM analysis results:

```javascript
// WRONG -- returns NodeList (not serializable)
() => document.querySelectorAll('h1')

// RIGHT -- returns serializable data
() => {
  const headings = [...document.querySelectorAll('h1,h2,h3,h4,h5,h6')];
  return headings.map(h => ({ tag: h.tagName, text: h.textContent.trim() }));
}
```

### Performance Considerations

| Operation | Cost | Mitigation |
|-----------|------|------------|
| `querySelectorAll('*')` on large DOM | O(n) where n = all elements | Acceptable for wireframes (typically < 500 elements) |
| `getComputedStyle()` per element | Triggers style recalculation | Batch reads, avoid interleaving with writes |
| `getBoundingClientRect()` per element | Triggers layout reflow | Same as above -- batch all reads |
| String concatenation in return | Memory proportional to DOM size | Cap output (e.g., first 50 violations only) |

**For wireframe/mockup HTML (typically 100-500 elements):** All operations complete in < 50ms. No optimization needed.

**For complex mockups (1000+ elements):** Limit `getComputedStyle` calls to text-containing elements only. The contrast checker already does this.

### Error Handling Inside Evaluate Scripts

```javascript
() => {
  try {
    // ... metric computation ...
    return { score: 85, details: { /* ... */ } };
  } catch (e) {
    // Return 0 score on error rather than throwing
    // (throwing inside evaluate causes the MCP call to fail)
    return { score: 0, error: e.message };
  }
}
```

**Critical rule:** Never let exceptions escape the evaluate function. The CJS metric script wrapping this call must always `exit(0)` per the `_evalMetric` contract. Catch errors inside the evaluate and return a default (typically 0 or a high violation count).

### Recommended Script Architecture

Each metric CJS script follows this pattern:

```javascript
#!/usr/bin/env node
'use strict';
// 1. Read file path from argv[1]
// 2. Start local server (npx serve) or construct file:// URL
// 3. Call Playwright MCP: browser_navigate to URL
// 4. Call Playwright MCP: browser_evaluate with metric function
// 5. Parse result, extract numeric score
// 6. Print score to stdout
// 7. Call browser_close (cleanup)
// 8. Exit 0 always
```

**Important constraint:** The CJS scripts cannot directly call MCP tools. They are invoked by the experiment runner, which has MCP access. The scripts should output the JavaScript function string that the experiment runner passes to `browser_evaluate`. Alternatively, the experiment runner can inline the evaluate call.

**Revised architecture (matching existing patterns):** The metric scripts likely need to be invoked through the experiment runner's MCP bridge, not as standalone processes. The experiment.md template specifies the verify command, and the runner handles the MCP orchestration. The metric scripts should:

1. Accept an HTML file path as argument
2. Use the MCP bridge to navigate + evaluate
3. Return the numeric score

OR (simpler): The metric scripts contain the JavaScript function as an exported string, and the experiment runner calls `browser_evaluate` with it. This matches how `nyquist-metric.cjs` wraps `node --test` -- the script is the orchestrator.

## 5. Implementation Recommendations

### Priority Order for Metric Scripts

1. **visual-metric.cjs** (VMET-01) -- DOM structure score. Simplest, most reusable, no resize needed.
2. **a11y-metric.cjs** (VMET-02) -- Violation count. Second simplest, single evaluate call.
3. **responsive-metric.cjs** (VMET-04) -- Multi-breakpoint. Requires 3x resize + evaluate orchestration.
4. **contrast-metric.cjs** (VMET-03) -- Contrast passes. Needs careful color parsing, MEDIUM confidence area.
5. **mermaid-metric.cjs** (VMET-05) -- Most complex, requires Mermaid JS library injection.

### Score Ranges

| Metric | Range | Direction | Interpretation |
|--------|-------|-----------|----------------|
| visual-metric | 0-100 | max | Higher = better DOM structure |
| a11y-metric | 0-N | min | Lower = fewer violations (0 = perfect) |
| contrast-metric | 0-N | max | Higher = more text/bg pairs passing WCAG AA |
| responsive-metric | 0-100 | max | Higher = better responsive compliance |
| mermaid-metric | 0-100 | max | Higher = more readable flow diagram |

## 6. Pitfalls and Edge Cases

### file:// URL Restrictions
Playwright headless Chrome may restrict `file://` URLs. The PLAY-05 requirement addresses this with a fallback to `npx serve`. Metric scripts must handle both paths.

### Transparent Background Traversal
The contrast checker cannot resolve inherited backgrounds through transparent layers. For wireframes/mockups that set explicit `background-color` on `body` or `main`, this is fine. For minimal CSS wireframes, many elements will have `rgba(0,0,0,0)` and be skipped. This means the contrast metric may report fewer pairs than expected -- acceptable for scoring purposes, but document it.

### Empty/Minimal HTML
A wireframe that is just `<html><body><h1>Title</h1></body></html>` should not crash any metric. All metrics must return 0 or a low score, not throw errors.

### Mermaid JS Loading
`mermaid-metric.cjs` needs Mermaid to render in-browser. Options: inject from CDN (`https://cdn.jsdelivr.net/npm/mermaid/dist/mermaid.min.js`), or bundle locally. CDN is simpler but adds a network dependency. Recommend CDN with a timeout fallback (return 0 if CDN unreachable).

### getComputedStyle on :hover/:focus States
`getComputedStyle` only returns the current state's styles. Cannot check hover/focus contrast without actually triggering those states. Acceptable limitation -- score the default state only.

### Multiple H1 Elements
HTML5 allows multiple h1 elements in sectioning contexts, but this is disputed and generally considered poor practice. The heading hierarchy checker should not penalize multiple h1s but should not give bonus points either.
