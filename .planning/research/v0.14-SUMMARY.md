v0.14 Visual AutoResearch is fully researchable and implementable. The milestone adds browser automation via Playwright MCP (7th APPROVED_SERVER) and exploits it to create 19 experiment types that optimize all 14 design skills against visual, accessibility, and structural metrics derived from actual browser rendering. All 10 phases (108-117) have clear implementation paths grounded in research.

**Key findings across all 8 research documents:**

1. **Playwright MCP infrastructure is well-understood** — stdio transport, `--headless --allow-unrestricted-file-access`, 10 tools needed (6 primary + 4 optional), file:// URLs work with the unrestricted flag, tool prefix is `mcp__playwright__*` (needs live verification). Existing pattern from Phase 44 (Stitch) applies exactly.

2. **All 5 visual metric scripts are implementable with zero npm deps** — standard Web APIs inside `browser_evaluate` cover DOM scoring, a11y violations, WCAG contrast, responsive compliance, and Mermaid readability. Each metric is a self-contained JS function string returning a single number.

3. **The experiment runner extension is minimal** — multi-candidate mode adds ~60 lines across 3 files, visual regression circuit breaker adds ~100 lines in one new module, JSONL schema extensions are backward-compatible.

4. **Meta-optimization is architecturally simple but needs 5 safety layers** — recursion depth guard, hard budget caps, child budget limits, wall-clock pre-spawn check, and ephemeral branch cleanup.

## Key Technical Decisions Validated by Research

### 1. Metric Architecture: Self-Contained JS Function Strings

Each metric script (visual, a11y, contrast, responsive, mermaid) embeds its evaluation logic as a JavaScript function string that `browser_evaluate` executes in page context. This avoids file-serving complexity, keeps scripts portable, and matches the existing `_evalMetric` contract.

**Confidence: HIGH** — DOM APIs are stable, `browser_evaluate` accepts arbitrary JS, return values are JSON-serializable.

### 2. WCAG 2.x for Primary Contrast Metric (Not APCA)

Use WCAG 2.1 AA (4.5:1 normal text, 3:1 large text) as the primary metric. APCA is promising but not yet normative (candidate for WCAG 3.0). The W3C relative luminance formula is ~40 lines of vanilla JS. `getComputedStyle` normalizes all color formats to rgb/rgba in Chromium.

**Confidence: HIGH** — W3C formulas are stable standards, Chromium color normalization confirmed.

### 3. Lightweight Custom A11y Checker (Not axe-core)

For metric scoring, a custom ~50-line checker (missing landmarks, broken headings, missing alt text, missing labels) beats axe-core injection (300KB+, CDN dependency). Reserve axe-core for critique workflow (A11Y-01/02) where rich descriptions matter.

**Confidence: HIGH** — DOM queries for a11y checks are trivial, axe-core is overkill for integer counting.

### 4. Mermaid via CDN + browser_evaluate

Render Mermaid flowcharts by writing a minimal HTML wrapper with CDN-loaded Mermaid v11, navigating Playwright to it, then evaluating SVG DOM metrics. 6-dimension scoring: node count (25%), edge density (20%), crossings (20%), label readability (15%), spacing (10%), viewport fit (10%).

**Confidence: HIGH for rendering, MEDIUM for scoring weights** — CSS class selectors need live verification (`.edgePath` vs `.edgepath`).

### 5. (1+N) Multi-Candidate Strategy with Sequential Commit/Reset

Generate N mutations from single parent, score each sequentially on same branch via commit/reset, keep best. Default N=1 (backward compatible), N=2 for visual experiments (sweet spot), N=3 maximum practical. Uses existing `_commit`/`_reset` primitives with one new `_resetToSha` helper.

**Confidence: HIGH** — grounded in existing codebase + EA literature.

### 6. SHA-256 Hash + Metric Direction for Visual Regression

`visual_regression = hash_changed AND metric_decreased`. Uses Node.js built-in `crypto.createHash('sha256')`. Baseline screenshot ratchets forward on KEEP only. Integrates as BREAK-05 in optimize.md, following existing BREAK-01..04 pattern.

**Confidence: HIGH** — pattern proven in manifest.cjs, zero dependencies.

### 7. Five-Layer Nested Loop Safety for Meta-Optimization

1. Hard budget caps (10 outer iterations, 120min)
2. `PDE_EXPERIMENT_DEPTH` env var guard (max depth 1)
3. Hardcoded child budget limits (5 iterations, 15min)
4. Wall-clock pre-spawn check
5. Ephemeral child branch cleanup

**Confidence: HIGH** — each layer is individually simple; all five are necessary.
