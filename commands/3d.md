# /pde:3d

Generate 3D models from text prompts or product images, optimize GLB files for web delivery, and embed with AR-capable model-viewer. All assets are stored in `.planning/design/3d/` with JSON metadata sidecars.

## Prerequisites

**HF_TOKEN** — Free Hugging Face access token required for text-to-3D and image-to-3D generation.

Get yours at: https://huggingface.co/settings/tokens

```
export HF_TOKEN=hf_your_token_here
```

## Usage

`/pde:3d <subcommand> [options]`

## Subcommands

### generate — Text-to-3D

Generate a 3D model from a text description. Uses a two-step pipeline: FLUX.1-schnell (HF Inference API) for text-to-image, then SF3D/InstantMesh (HF Gradio Space) for image-to-GLB.

```
/pde:3d generate --prompt <text> [--slug <slug>]
```

Options:
- `--prompt` — Text description of the desired 3D model (required)
- `--slug` — Identifier slug for output filename (default: `model`)

Output: JSON metadata for the generated GLB asset.

Example:
```
/pde:3d generate --prompt "a ceramic coffee mug with blue glaze" --slug coffee-mug
/pde:3d generate --prompt "minimalist white sneaker product shot" --slug sneaker
```

### convert — Image-to-3D

Convert a product image to a 3D GLB file via HF Gradio Space. Tries SF3D (stabilityai/stable-fast-3d) first, then InstantMesh (TencentARC/InstantMesh) as fallback.

```
/pde:3d convert --image <path> [--slug <slug>]
```

Options:
- `--image` — Path to input image file (required)
- `--slug` — Identifier slug for output filename (default: `model`)

Output: JSON metadata for the converted GLB asset.

Example:
```
/pde:3d convert --image product-photo.jpg --slug widget
/pde:3d convert --image .planning/design/assets/og-2024.png --slug og-model
```

### optimize — Optimize GLB for Web

Optimize a GLB file using Draco compression and texture resize, targeting under 5MB for fast web loading.

```
/pde:3d optimize --input <path.glb> [--output <path.glb>] [--texture-max <px>]
```

Options:
- `--input` — Path to source GLB file (required)
- `--output` — Path for optimized output (default: `<input>-opt.glb`)
- `--texture-max` — Maximum texture dimension in pixels (default: `1024`)

Output: JSON with `outputPath` and `sizeMB`.

Example:
```
/pde:3d optimize --input model.glb --output model-web.glb --texture-max 512
/pde:3d optimize --input .planning/design/3d/coffee-mug-1234.glb
```

### embed — Generate model-viewer Embed

Generate a model-viewer HTML embed snippet and self-contained HTML page with AR fallback. Supports WebXR (Android Chrome), Scene Viewer (Android), and iOS Quick Look (USDZ auto-generated by model-viewer).

```
/pde:3d embed --glb <path.glb> [--slug <slug>] [--camera-orbit <orbit>]
```

Options:
- `--glb` — Path to GLB file (required)
- `--slug` — Identifier slug for embed filename (default: `model`)
- `--camera-orbit` — Camera orbit attribute value (default: `45deg 75deg 2m`)

Output: JSON with `embedPath` and `snippet`. The HTML file is saved to `.planning/design/3d/<slug>-embed.html`.

Example:
```
/pde:3d embed --glb .planning/design/3d/coffee-mug-1234.glb --slug coffee-mug
/pde:3d embed --glb model.glb --slug product --camera-orbit "30deg 60deg 3m"
```

### list — List 3D Assets

List all 3D assets stored in `.planning/design/3d/` with their metadata.

```
/pde:3d list
```

Output: JSON array of asset metadata objects. Returns empty array if no assets exist.

Example:
```
/pde:3d list
```

### cad -- Parametric CAD Generation

Generate a parametric CadQuery Python script from a product description, execute it via Python subprocess, and export a STEP file for engineering handoff.

**Requires:** CadQuery installed in a Python venv. Set `CADQUERY_PYTHON` env var to the venv python path.

```
/pde:3d cad --description <text> [--slug <slug>]
```

Options:
- `--description` -- Text description of the hardware product to model (required)
- `--slug` -- Identifier slug for output filename (default: `cad-model`)

Output: JSON metadata for the generated STEP asset. The STEP file, source CadQuery script (.cq.py), and metadata sidecar are saved to `.planning/design/3d/`.

Example:
```
/pde:3d cad --description "rectangular electronics enclosure 120x80x40mm with 3mm walls and rounded edges" --slug enclosure
/pde:3d cad --description "L-shaped mounting bracket 50x30mm with 4mm holes" --slug bracket
```

Setup (one-time):
```bash
python3.11 -m venv ~/cadquery-env
source ~/cadquery-env/bin/activate
pip install cadquery
export CADQUERY_PYTHON=~/cadquery-env/bin/python3
```

## Output

All commands output JSON to stdout. GLB files and metadata sidecars are stored in `.planning/design/3d/`.

Asset metadata includes: `source_model`, `input_type`, `slug`, `timestamp`, `file_size`, `vertex_count`, `glb_path`.
CAD assets include: `source_script`, `params`, `slug`, `timestamp`, `file_size`, `step_version`, `step_path`.

## Notes

- **HF Space availability:** HF Spaces can be intermittently unavailable. The pipeline tries SF3D first, then InstantMesh. Temporary unavailability produces a warning — retry after a few minutes.
- **AR on iOS:** model-viewer automatically handles USDZ generation for iOS Quick Look — no server-side USDZ conversion needed.
- **Local GPU inference (optional):** For private, offline, or GPU-accelerated inference, see the Python TripoSR setup guide at https://github.com/VAST-AI-Research/TripoSR
- **Optimization requirement:** `gltf-transform` must be available (`npm install @gltf-transform/cli`) for the optimize subcommand and automatic optimization during conversion.
- **CadQuery requirement:** The `cad` subcommand requires CadQuery installed in a Python venv. Set `CADQUERY_PYTHON` to the venv python3 path. CadQuery is not available via npm -- it is a Python package using the OpenCASCADE geometry kernel.
